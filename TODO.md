### Этап 2. Данные моделей и списки отрисовки
Целевой порядок кадра: CPU (update, отсечение, LOD, списки отрисовки с сортировкой) → compute (расстановка, частицы, окружение неба) → тени солнца → непрозрачные и masked → небо на дальней плоскости с тестом глубины → прозрачные по удалению → цепочка постобработки → GUI.
- [ ] Режим материала, как Blend Mode и Two Sided в UE: `Opaque` / `Masked` (отсечение по альфе с порогом) / `Translucent` и двусторонность — свойства материала или его экземпляра, по ним списки отрисовки выбирают проход и состояние растеризатора. Сейчас проход задаёт объект, `ModelQueues` рисует всё с отсечением задних граней, `PBRInstance` зашит на порог альфы 0,9 через define. Импортёр переносит `alphaMode`, `alphaCutoff` и `doubleSided` из glTF. Заменяет пункт про двусторонние модели
- [ ] Проходы — жёсткий enum `RenderPass { sky, opaque, transparent }` (`Scene/SceneObject.h`), каждый объект сам рисует себя с главной камеры в `render()`. Проход с другой точки зрения (тени солнца, отражения воды) или «только глубина» (depth prepass) требует правки каждого объекта. Решение: объекты отдают элементы отрисовки (меш, материал, матрица, флаги проходов, ключ сортировки), а нестандартные (террейн, расстановка, небо, частицы) — обработчик по проходу с флагами «умею глубину / отбрасываю тень»; порядком проходов и видами (главная камера, каскады теней) владеет `Renderer` — как mesh draw commands в UE. Без этого не сделать тени. Главный пункт этапа. Новый код — без синглтонов: рендерер передаёт проходам контекст. Элемент отрисовки несёт и признак зеркальности: при отрицательном определителе мировой матрицы (отрицательный масштаб экземпляра) — отсечение передних граней вместо задних, как в UE; сейчас такой экземпляр рисуется наизнанку, поэтому импортёр зеркальные объекты запекает в вершины
- [ ] Модели не отсекаются по frustum: `ModelQueues::update` выбирает только LOD по расстоянию и рисует все модели уровня; одинаковые модели — отдельными вызовами, без инстансинга. Делать в сборе списков отрисовки, а не в нынешнем `ModelQueues` — иначе переписывать дважды. Экземпляры (`LevelModels`, `DMTransform`) уже есть: одинаковые LOD экземпляров собираются в один `DrawIndexedInstanced` с буфером матриц. Границы — AABB меша (считать при загрузке) × мировая матрица экземпляра; `DMAABB` (`Common/DMAABB.h`) сейчас нигде не используется — взять за основу или заменить на `DirectX::BoundingBox`
- [ ] Небо рисуется первым на весь экран без теста глубины (`SkyAtmosphere::render` в проходе `sky`), затем почти всё закрывает террейн — лишняя перерисовка всего кадра. Рисовать небо после непрозрачных на дальней плоскости с тестом глубины `LESS_EQUAL`. Вместе со списками: проход неба становится обычным элементом с тестом глубины
- [ ] Прозрачный проход не сортируется: `Renderer::renderPass` идёт по объектам в порядке `Scene::objects()`; alpha-to-coverage в состоянии блендинга без MSAA не работает. Прозрачные — сортировать сзади вперёд, сортировка — в списках отрисовки. Трава уже переведена на `PBR` в непрозрачном проходе (пучки `GrassClump` — геометрия, альфа не нужна). Осталось: ромашки — карточки без текстуры (шахматка): сделать цветок в Blender, лепестки альфа-карточкой — пример режима `Masked`; затем удалить материалы `VertexLight` (10, 11) и старые модели травы GrassBlade, GrassCross с их экземплярами — их больше никто не использует (закрывает и пункт про цвет травы из текстуры земли в `VertexLight.ps`). Заодно убрать материал `Grass` (id 6, `DMGrassShader`, `Shaders/grass.vs|ps`): ни одна модель его не использует, а `grass.ps` занимает под свой буфер слот b1 — это слот матрицы объекта (`SLOT_CB_OBJECT`)

### Этап 4. Свет и окружение как данные уровня, физические единицы
- [ ] Источники — глобальный `Scene\Lights.ini`, общий для всех уровней, а не данные уровня; не больше 32 (`DMLightDriver::maxLights`); в GUI не редактируются и не выключаются (`DMLight::enabled` всегда true); `setBuffer` каждый кадр сортирует и заново загружает список. Источники уровня — в БД (`LevelLights`: тип, цвет, интенсивность, радиус, конус — имена уже как в UE и KHR_lights_punctual) с правкой в GUI; буфер обновлять только при изменении. Вместе с источниками перенести в данные уровня настройки неба (`[Sky]`) и постобработки (`[PostProcess]`) — одним заходом, а не трижды
- [ ] Цвет прямого света солнца от атмосферы (как Atmosphere Sun Light в UE): источник задаётся над атмосферой, у земли его цвет — пропускание по пути луча; сейчас на закате небо оранжевое, а свет — белый из `Lights.ini`. Вместе с этим — время суток (положение солнца) в GUI. Одним заходом с физическими единицами: солнце задаётся над атмосферой в люксах
- [ ] Постобработка — один проход (`PostProcess`). Для bloom (солнечный диск и блики сейчас просто белые), автоэкспозиции, цветокоррекции (LUT) и сглаживания нужна цепочка проходов с промежуточными целями. До автоэкспозиции: ей нужны проходы гистограммы и средней яркости
- [ ] Автоэкспозиция (адаптация по гистограмме яркости кадра, как Auto Exposure в UE) и физические единицы света (люксы для солнца, кд/м² для неба, EV100, канделы или люмены для точечных и прожекторов) вместо условных яркостей под 0 EV. Цвет и интенсивность источника — раздельно, как в glTF и UE (сейчас `Color` — цвет × яркость). Физические единицы и автоэкспозиция — вместе: с единицами в люксах ручные 0 EV больше не подходят, и калибровать яркость дважды не придётся
