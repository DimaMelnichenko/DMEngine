# Модели: импорт из Blender (glTF)

Модели попадают в движок так же, как в Unreal Engine: из Blender экспортируется обменный формат glTF 2.0, а импортёр
`Tools/import_gltf.py` один раз переводит его во внутренние данные движка — файлы мешей в формате, который читает
`MeshLoader`, картинки текстур и строки `base.db3`. Во время игры glTF не читается.

Возможности:

- статические меши с нормалями, развёрткой и касательными (MikkTSpace из Blender);
- LOD по суффиксу `_LOD<N>` в имени объекта;
- материал glTF переносится в материал `PBR` один в один (см. [materials.md](materials.md));
- картинки из `.glb` или рядом с `.gltf` копируются как есть, цветовое пространство ставится по назначению текстуры;
- расстановка на уровне с положением, поворотом и масштабом объектов из Blender; связанные дубликаты (Alt+D) —
  экземпляры одной модели;
- повторный импорт того же файла обновляет модель (reimport), `--dry-run` показывает, что будет записано.

## Экспорт из Blender

File → Export → glTF 2.0:

| Настройка | Значение | Зачем |
|---|---|---|
| Format | glTF Binary (`.glb`) | один файл с мешами и картинками; `.gltf` с отдельными файлами тоже читается |
| Include → Selected Objects | по желанию | в файл попадают только выбранные объекты |
| Transform → +Y Up | включено (по умолчанию) | ось Y вверх, как в движке |
| Data → Mesh → Apply Modifiers | включено | модификаторы (Solidify, Decimate, Bevel) применяются |
| Data → Mesh → UVs, Normals | включено | |
| Data → Mesh → Tangents | включено | точные касательные MikkTSpace; без них импортёр считает их сам по развёртке |
| Data → Material → Images | Automatic или PNG | JPEG тоже годится; WebP и сжатие KTX2 не поддерживаются |
| Data → Compression | выключено | Draco и meshopt не поддерживаются |
| Animation | выключено у статичных моделей | скелет и клипы импортируются у модели со скином ([animation.md](animation.md)); морфинг — нет |

Единицы: 1 единица Blender = 1 метр движка. В Blender у нового материала Backface Culling выключен, и экспорт помечает
его двусторонним — движок так его и рисует, без отсечения задних граней. Замкнутому мешу это не нужно: включите
Backface Culling в настройках материала (импортёр напоминает об этом списком двусторонних материалов). Отсечение по
альфе (Masked) — узел Math → Round между альфой текстуры и входом Alpha: экспортёр пишет `alphaMode: MASK`.

## Как устроить сцену в Blender

- **Объект = модель.** Имя модели — имя объекта (символы кроме латиницы, цифр, `_` и `-` заменяются на `_`).
- **LOD.** Объекты `Rock`, `Rock_LOD1`, `Rock_LOD2` — одна модель `Rock` с тремя уровнями детализации. Положение
  объектов LOD в сцене не важно: каждый берётся относительно своего origin (их поворот и масштаб — относительно `Rock`). Дальности переключения — `--lod-ranges`,
  по умолчанию 25, 50, 100 … м, последний LOD — до 10000 м, то есть до дальней плоскости камеры (`ScreenDepth` в `settings.ini`, 4000 м). Расстояние считается от камеры до опорной точки модели.
  Если в материале секции включён `DitheredLODTransition` ([materials.md](materials.md)), LOD сменяется плавно, как
  Dithered LOD Transition в UE. В полосе «дальность ± 5 %» (`Shaders/lod_transition.h`) экземпляр рисуется обоими LOD
  (`ModelInstances::addLod`), каждый — своей долей пикселей экрана, маски дополняют друг друга. За последним LOD
  экземпляр так же растворяется. Такие меши рисуются по одному, а не инстансным вызовом: доля перехода — в константах
  объекта (`cb_lodDither`). Без флага LOD сменяется мгновенно на дальности. У `TestRock` флаг включён: на 25 м видна
  смесь двух сеток.
- **Материалы объекта — секции.** Как sections / material slots у Static Mesh в UE и primitives у меша glTF: LOD
  модели — список секций, у секции свой меш и свой материал (примитивы одного материала сливаются в один меш). Номер
  секции — слот материала: порядок его появления в LOD0 и дальше, одинаковый во всех LOD; в LOD, где материала нет,
  нет и секции. Так у дерева непрозрачный ствол и Masked хвоя, у растения — стебель и лепестки: режим (проход,
  отсечение граней) у каждой секции свой. Секция — отдельный вызов отрисовки; меньше вызовов — атлас с одним
  материалом, но тогда режим у всех частей один.
- **Опорная точка — origin объекта.** Вершины остаются в координатах объекта, а его положение, поворот и масштаб
  становятся экземпляром модели на уровне (`LevelModels`) — как Location / Rotation / Scale актора в UE. Модели для
  расстановки ставятся своим origin на землю, поэтому у них origin должен быть внизу; их поворот и масштаб из Blender
  запекаются в вершины (расстановка задаёт свои).
- **Экземпляры.** Связанные дубликаты (Alt+D — объекты с общим мешем) становятся одной моделью с несколькими строками
  `LevelModels`: меш и материал хранятся один раз. Обычная копия (Shift+D) — отдельная модель. Дубликат с модификаторами
  при экспорте с Apply Modifiers получает свой меш и тоже становится отдельной моделью.
- Отрицательный масштаб (зеркало) допустим: зеркальный объект становится экземпляром с масштабом −1 по X, и движок
  рисует его с обратным обходом лицевых граней (как UE) — освещение и карта нормалей верны. В вершины запекается
  только сдвиг осей, который даёт неравномерный масштаб родителя под повёрнутым потомком (импортёр предупреждает).

## Что переносится из материала glTF

| glTF | Параметр `PBR` | Примечание |
|---|---|---|
| `baseColorTexture`, `baseColorFactor` | `BaseColor`, `BaseColorFactor` | текстура sRGB |
| `metallicRoughnessTexture` | `MetallicRoughness` | линейная; G — шероховатость, B — металличность, как в glTF |
| `metallicFactor`, `roughnessFactor` | `Metallic`, `Roughness` | по умолчанию glTF — 1 и 1 |
| `normalTexture`, `scale` | `Normal`, `NormalScale` | линейная; `NormalGreenUp = true` (карты glTF в соглашении OpenGL) |
| `occlusionTexture`, `strength` | `Occlusion`, `OcclusionStrength` | линейная; может быть той же картинкой, что `MetallicRoughness` (ORM) |
| `emissiveTexture`, `emissiveFactor`, `KHR_materials_emissive_strength` | `Emissive`, `EmissiveFactor` | текстура sRGB, сила свечения умножается на множитель |
| `alphaMode`, `alphaCutoff` | `AlphaMode`, `AlphaCutoff` | OPAQUE → 0, MASK → 1, BLEND → 2 (импортёр предупреждает: полупрозрачные сортируются по опорной точке) |
| `doubleSided` | `DoubleSided` | без отсечения задних граней, см. [materials.md](materials.md) |
| `KHR_materials_diffuse_transmission`: `diffuseTransmissionFactor`, `diffuseTransmissionColorFactor`, `diffuseTransmissionColorTexture` | `DiffuseTransmissionFactor`, `DiffuseTransmissionColorFactor`, `DiffuseTransmissionColor` | свет сквозь тонкую поверхность (листья); текстура sRGB; `diffuseTransmissionTexture` пропускается с предупреждением |
| `KHR_materials_specular`: `specularFactor` | `SpecularFactor` | сила отражения диэлектрика; `specularTexture` и цвет отражения пропускаются с предупреждением |

**Параметры движка без аналога в glTF** — `extras` материала: Custom Properties материала Blender (экспорт с
`export_extras`). Имена — как у параметров `PBR` ([materials.md](materials.md)): `DitheredLODTransition`, `WindWeight`,
`DiffuseTransmission*`. Это нужно в первую очередь для пропускания: экспортёр glTF Blender
`KHR_materials_diffuse_transmission` не пишет. Значения переносятся так:
- bool — `true` / `false`;
- число — как есть;
- список — через запятую;
- строка с именем текстуры материала (`BaseColor`) — та же текстура. Например, `DiffuseTransmissionColor = BaseColor`:
  цвет света насквозь — текстура хвои.

Неизвестное имя — ошибка импорта. Так передаёт параметры ель (`Tools/blender_fir.py`).

**Ветер дерева** — собственные атрибуты вершин glTF `_WIND_BRANCH1`, `_WIND_BRANCH2` (VEC4) и `_WIND_WEIGHTS` (VEC2),
как входы Games wind SpeedTree ([wind.md](wind.md)). Экспорт из Blender — с `export_attributes`; начала ветвей
записываются в осях glTF, как позиции. Импортёр переводит начала матрицей узла и зеркалом, пишет блок `WIND` в файл
меша, а секциям с этими данными ставит материал `PBRTree` (id 13). Прежний экземпляр с тем же именем у другого
материала, если на него больше не ссылается ни одна секция, удаляется.

Не переносятся (импортёр предупреждает): вторая развёртка (`texCoord` ≠ 0), `KHR_texture_transform`, режимы повтора текстуры кроме
REPEAT, цвета вершин и остальные расширения материала `KHR_materials_*` (clear coat, sheen, transmission…). Примитив без
материала получает материал glTF по умолчанию: белый, metallic 1, roughness 1.

## Запуск

```
python Tools/import_gltf.py модель.glb [--level ValleyOfStreams --position x,y,z [--snap-to-terrain]] [--scale s]
                                       [--lod-ranges 25,60] [--shadow-lod-scale 0.5] [--shadow-min-lod 2] [--name Имя]
                                       [--collision hull|box|mesh|capsule|none] [--collision-radius r] [--asset папка]
                                       [--scatter] [--dry-run]
```

| Параметр | Что делает |
|---|---|
| `--level`, `--position` | ставит модели на уровень: origin файла в точке `x,y,z`, каждый объект — со своими положением, поворотом и масштабом из Blender |
| `--snap-to-terrain` | ставит экземпляры на землю уровня, как Drop to surface в UE: высота — террейн в точке (x, z) плюс высота объекта над нулём в Blender, `y` в `--position` не учитывается (`Tools/terrain.py`: та же выборка карты высот, что у движка) |
| `--scale` | равномерный масштаб на уровне (и положений объектов тоже); с `--scatter` — запекается в вершины |
| `--lod-ranges` | дальности LOD в метрах: на один меньше числа LOD (последний — 10000) или по одной на каждый |
| `--shadow-lod-scale` | множитель дальностей LOD у теней (`Models.shadow_lod_scale`, 0,1…1; без опции не меняется, у новой модели 1) — см. «LOD теней» |
| `--shadow-min-lod` | LOD у теней не детальнее этого (`Models.shadow_min_lod`; без опции не меняется, у новой модели 0) — см. «LOD теней» |
| `--name` | имя модели вместо имени объекта — для файла с одной моделью |
| `--collision` | простая коллизия моделей файла (`Models.collision`): `hull` — оболочка вершин LOD0, `box` — коробка по границам, `mesh` — треугольники, `capsule` — ствол дерева, `none` — без столкновений ([physics.md](physics.md)); без опции — extras «collision» объекта LOD0 (Custom Property объекта в Blender), иначе не меняется (у новой модели NULL — оболочка) |
| `--collision-radius` | радиус ствола у `capsule`, м в единицах модели (`Models.collision_radius`); без опции — extras «collision_radius» объекта LOD0, иначе не меняется (NULL — по основанию модели: у дерева с лапами у земли выйдет радиус кроны) |
| `--asset` | папка и префикс файлов и текстур вместо имени файла |
| `--scatter` | модель для слоёв расстановки: материал `PBRInstance`, `render = 0`, без `--level`; дальности LOD (`--lod-ranges`) расстановка тоже берёт из модели (см. [scatter.md](scatter.md)) |
| `--dry-run` | напечатать, что будет записано, и ничего не менять |

Скрипт печатает для каждой модели число вершин и треугольников LOD, экземпляр материала, габариты в координатах
объекта и её экземпляры на уровне — по ним удобно подобрать `--position` (высота земли под моделью — `y`).

## Что и куда пишется

| Где | Что |
|---|---|
| `Meshes\models\<ассет>\<модель>_LOD<N>[_S<k>].bin` | меш секции (секция 0 — без суффикса): заголовок (число вершин, индексов), вершины по 56 байт — позиция, нормаль, UV, касательная, бинормаль, индексы `uint32`; затем необязательные блоки — 4 байта метки и данные на вершину: `WIND` (ветер дерева, 40 байт, [wind.md](wind.md)), `SKIN` (4 кости `uint8` и 4 веса `unorm8`, 8 байт) |
| `Meshes\models\<ассет>\<модель>.skel`, `<модель>_<клип>.anim` | модель со скелетом: скелет и клипы ([animation.md](animation.md), «Файлы») |
| `Textures\models\<ассет>\<картинка>.png` | картинки без перекодирования |
| `Meshes` | строка на секцию LOD: имя `<модель>_LOD<N>[_S<k>]`, файл, `primitive = box` — заглушка, если файла нет (каталог не в git) |
| `Textures` | имя `<ассет>_<картинка>`, файл, мипы, `sRGB` — 1 для базового цвета и свечения, 0 для остального; `compression` — `normalmap` (BC5) у карты нормалей, `default` (BC7) у прочих ([materials.md](materials.md), «Сжатие и приготовление текстур») |
| `MaterialInstance`, `MaterialParameterInstance` | экземпляр `<ассет>/<материал>` материала `PBR` (12) или `PBRInstance` (9) и его значения |
| `Models`, `ModelProperties` | модель (`shadow_lod_scale`, `shadow_min_lod` — LOD теней, `collision` и `collision_radius` — простая коллизия, [physics.md](physics.md), `canopy` — крона дерева на карте полога: множитель радиуса, NULL — не дерево, [scatter.md](scatter.md), «Полог»; `broadleaf` — 1 у лиственного: под кроной подстилка из листьев, [terrain.md](terrain.md), «Подстилка под кронами») и её LOD: строка на секцию (`lod`, `section`) — меш, материал, экземпляр; дальность и `render` LOD — у секции 0 |
| `LevelModels` | с `--level`: экземпляры модели на уровне — положение, поворот, масштаб (см. ниже), у модели со скелетом — клип `--animation` (`animation_id`) |
| `Skeletons`, `Animations`, `Models.skeleton_id` | модель со скелетом: скелет, клипы и точки шага по скорости и повороту (`--locomotion`) |
| `LevelLights` | с `--level`: источники света файла (`KHR_lights_punctual`) — см. «Источники света из Blender» |

Всё пишется в одной транзакции. Модели, меши, текстуры и экземпляры материалов находятся по именам, поэтому повторный
импорт того же файла обновляет их, а не добавляет новые; меши LOD, которых больше нет, удаляются. Строки `LevelModels`
импортируемых моделей на этом уровне заменяются заново: правки расстановки, сделанные в базе вручную, повторный
импорт перезаписывает. Каталоги `Meshes\` и
`Textures\` в git не хранятся — держите исходный `.blend` или `.glb` у себя, модель восстанавливается повторным импортом.

## Модель со скелетом

Файл со скином (`skins[0]`) импортируется одной моделью со скелетом, как Skeletal Mesh в UE ([animation.md](animation.md)).
- Секции — сетки со скином и сетки на костях (узел-потомок кости без скина: рога на голове — вес 1 этой кости) по
  материалам; LOD — по суффиксу `_LOD<N>` имени узла.
- Вершины — в позе покоя в пространстве модели, `--scale` и узлы над скелетом запекаются в скелет и вершины (экземпляр на
  уровне — без масштаба).
- Перед модели glTF (+Z) — перед движка: модель со скелетом поворачивается на 180° вокруг вертикали (у статичных — как
  прежде).
- Клипы — в файлы `.anim` с частотой 30 Гц, движение корня вынесено. Кость корня — `--root-motion-bone` или первая, что
  уходит по горизонтали.
- `--locomotion "<покой>,<шаг>,<шаг влево>,<шаг вправо>,<рысь>[=скорость]"` — точки шага по скорости и повороту:
  скорость и поворот — по движению корня, клип с поворотом — вариант влево или вправо аллюра ближайшей скорости.
- `--collision capsule --collision-radius <м>` — у зверя капсула по ширине тела: тело экземпляра уровня и персонаж
  сущности ([physics.md](physics.md)).
- `--animation <клип>` — клип экземпляров уровня.

Материалы `KHR_materials_pbrSpecularGlossiness` (Sketchfab) переводятся в `PBR`: диффузный цвет — базовый, шероховатость
— 1 − глянец, `SpecularFactor` — F0 / 0,04. У картинки без имени имя — её файла.

Архив Sketchfab (glTF: `scene.gltf`, `scene.bin`, `textures\`) — распаковать в `Meshes\source\<имя>\`, `--asset` задаёт
папку файлов (имя файла `scene` — общее у всех архивов):

```
python Tools/import_gltf.py Meshes/source/<имя>/scene.gltf --asset <имя> --name <Модель> --level ValleyOfStreams --position x,0,z
    --snap-to-terrain --animation <клип> --collision capsule --collision-radius 0.45
    --locomotion "<покой>,<шаг>,<шаг влево>,<шаг вправо>,<рысь>,<бег>"
```

Импорт в Blender у части моделей ломает клипы (IK-кости ног выворачиваются) — импортёр читает glTF сам и считает по
спецификации; позу клипа можно проверить скиннингом по файлу на numpy.

## Источники света из Blender

Источники сцены Blender (Point, Spot, Sun; Area и Hemi экспортёр не пишет) переходят в строки `LevelLights` уровня —
как источники в уровне UE ([lighting.md](lighting.md)). В Blender при экспорте glTF включите **Punctual Lights**
(`export_lights=True`), режим единиц — **Standard** (по умолчанию): экспортёр сам переводит ватты Blender в единицы
glTF, а они совпадают с `LevelLights` — перевода не нужно:

| Blender | glTF | `LevelLights` |
|---|---|---|
| Point, мощность P, Вт | `point`, `intensity` = P / 4π × 683, кд | `point`, `intensity`, кд |
| Spot, мощность P, Вт; Size; Blend | `spot`, кд как у Point; `outerConeAngle` = Size / 2, `innerConeAngle` = внешний × (1 − Blend) | `spot`, `outer_cone_angle` / `inner_cone_angle`, градусы |
| Sun, Strength S, Вт/м² | `directional`, `intensity` = S × 683, лк | `directional`, `intensity`, лк |
| Custom Distance | `range`, м | `attenuation_radius` (нет — без обрезания) |
| цвет, Temperature | `color` | `color` |

Ориентиры: лампа ~100 кд — Point 1,8 Вт; полуденное солнце ~100 000 лк — Sun 146 Вт/м². Направление — ось −Z объекта
(Blender светит вдоль неё, как glTF), место — origin объекта относительно `--position` с масштабом `--scale`; с
`--snap-to-terrain` высота над нулём в Blender — высота над землёй, как у экземпляров. Имя строки — имя объекта:
повторный импорт обновляет строку источника уровня с тем же именем (тип, цвет, интенсивность, место, направление,
радиус, конус), а выключатель и тени, заданные на уровне, остаются; источник, убранный в Blender, на уровне остаётся —
уберите его в редакторе (Delete) или в базе. Новый направленный — без атмосферы и теней, если у уровня уже есть
направленный (солнце уровня — первый по `id`), иначе он и есть солнце: с атмосферой и тенями. Файл может быть и без
мешей — только источники. Без `--level` источники пропускаются с предупреждением.

## Модели на уровне: `LevelModels`

Строка — экземпляр модели на уровне; у одной модели строк может быть сколько угодно. Модель (меши LOD, материалы)
загружается один раз, экземпляры рисуются каждый со своей мировой матрицей.

| Колонка | Пример | Что это |
|---|---|---|
| `level`, `model` | 1, 23 | уровень (`Levels.id`) и модель (`Models.id`) |
| `position` | `473,91.7,238` | положение origin модели в мире, м |
| `rotation` | `0,0.382683,0,0.92388` | поворот — кватернион `x,y,z,w`, как `rotation` узла glTF и FQuat в UE; по умолчанию `0,0,0,1` |
| `scale` | `1,1,1` | масштаб по осям модели, может быть неравномерным |

Мировая матрица — масштаб, затем поворот, затем сдвиг (`DMTransform`). Экземпляр вне поля зрения не рисуется
(границы меша, переведённые его матрицей, проверяются по frustum), а одинаковые — та же модель в том же LOD, с тем же
отсечением граней — рисуются одним инстансным вызовом: сотня одинаковых камней стоит почти как один. Поворот на угол a вокруг оси (x, y, z) единичной
длины — кватернион `x·sin(a/2), y·sin(a/2), z·sin(a/2), cos(a/2)`: например, 45° вокруг Y — `0,0.382683,0,0.92388`
(система левая: положительный поворот вокруг Y ведёт +Z к +X, по часовой стрелке при взгляде сверху). Нормали
преобразуются обратной транспонированной матрицей, поэтому неравномерный масштаб их не искажает.

В редакторе — окно «Model instances» (Outliner → Scene): подокно на экземпляр `id: модель` с «Position» (м), «Rotation»
(градусы: Pitch вокруг X, Yaw вокруг Y, Roll вокруг Z — порядок `XMQuaternionRotationRollPitchYaw`, как Rotation в
Details UE) и «Scale». Правка сразу двигает экземпляр, его тень и границы сцены; «Save level» (Ctrl+S) пишет строки
`LevelModels` по `id`, поворот — кватернионом из углов ([gui.md](gui.md)). Подокно «Add» — кнопка на модель уровня: новый
экземпляр перед камерой на земле; «Delete» у подокна экземпляра и Delete во вьюпорте — убрать (Ctrl+Z вернёт); «Save
level» вставляет новые строки `LevelModels` и удаляет строки убранных ([gui.md](gui.md), «Вьюпорт»). Окно «Models» —
параметры материалов секций моделей и «Shadow LOD scale» / «Shadow min LOD» у моделей с несколькими LOD, они не
сохраняются.

**LOD теней.** В каскадах теней дальности LOD модели умножаются на `Models.shadow_lod_scale` («Shadow LOD scale» окна
«Models», `DMModel::shadowLodScale`; дальность последнего LOD — конец модели — не меняется): 0,5 — тень более грубым LOD
вдвое ближе, чем в кадре. Тень ближнего экземпляра — от той же геометрии, что в кадре: он затеняет себя сам, и грубый LOD
заметнее всего именно на нём, а у дальних мелкие карточки в тени не видны. Так же, как у LOD кадра, считаются от главной
камеры (`RenderView::lodOrigin`), полоса перехода — с дизерингом у каждого вида своя (`ModelInstances::collectMeshes`).
Множитель берёт и расстановка: у варианта слоя — для границ LOD модели, вместе с множителем набора
([scatter.md](scatter.md), «LOD теней»). Значение — опция `--shadow-lod-scale` импорта или правка строки `Models`; в окне
«Models» — подбор вживую. Сейчас 0,5 — у елей (см. «Ель»). `Models.shadow_min_lod` («Shadow min LOD») — тень не
детальнее этого LOD и у ближних экземпляров (`--shadow-min-lod`; не дальше последнего LOD): у травы 2 — тень луга от
самого грубого LOD пучков ([scatter.md](scatter.md), «Трава: пучок из Blender»).

## Геометрия: из glTF в движок

glTF — правосторонняя система (Y вверх, лицом к +Z), движок — левосторонняя (Y вверх), обе в метрах. Импортёр:

1. раскладывает мировую матрицу объекта на положение, поворот и масштаб — экземпляр на уровне; поворот переводится
   в левую систему (у кватерниона меняют знак x и y), зеркальная матрица даёт отрицательный масштаб по X. Если
   у матрицы сдвиг осей, а также для `--scatter`, поворот и масштаб применяются к вершинам (нормали — обратной
   транспонированной матрицей);
2. меняет знак Z у позиций, нормалей, касательных и положения экземпляра;
3. меняет местами две вершины каждого треугольника: после зеркала лицевая сторона оказалась бы изнанкой;
4. пишет бинормаль по соглашению движка — направление роста v (вниз по картинке); карта нормалей glTF читается
   материалом с `NormalGreenUp = true`.

UV копируются без изменений: у glTF, как у Direct3D, v = 0 — верх картинки.

## Модели Poly Haven

Растения и камни Poly Haven (CC0) скачиваются архивом `.blend` в `DownloadResources\` (не в git):
`python Tools/polyhaven_download.py rock_moss_set_01 --resolution 2k` берёт `.blend` и его текстуры через API
Poly Haven и складывает `<ассет>_<разрешение>.blend.zip` в раскладке архива с сайта (`--list` — разрешения и
размеры: у `fir_tree_01` в 2k — 406 МБ). Как есть экспортёр
glTF их не понимает: материалы собраны на узлах-группах (цвет, «сухой» цвет, альфа, подповерхностное рассеяние),
альфа — отдельной картинкой, нормали и шероховатость — в EXR. `Tools/export_polyhaven.py` (Blender без окна) готовит
из архива `.glb` для импорта с `--scatter`:

- объекты — по регулярному выражению `--objects`; служебные копии (`geonodes_`, `_geo`, шар превью) отбрасывает `--exclude`;
- LOD — суффикс `_LOD<N>` Poly Haven; `--lod-offset k` отбрасывает LOD ниже k (у одуванчика LOD0 — 23 тыс. треугольников);
  у объектов без LOD (камни, 5–16 тыс. треугольников) `--decimate-tris` строит их модификатором Decimate;
- материал собирается заново простым Principled BSDF, картинки — до `--texture-size` (2048): базовый цвет с альфой из
  отдельной карты (через Round — `alphaMode: MASK`), шероховатость — в G `metallicRoughness`, нормаль (OpenGL, как
  в glTF) — в 8-битный PNG; двусторонний, как у исходного материала, или по `--double-sided` / `--single-sided`;
- параметры движка, которых нет в glTF, — `--material-param ИМЯ=ЗНАЧЕНИЕ` (повторяется, всем материалам): в
  `extras`, как у ели. Значения: `true` / `false`, числа через запятую, имя текстуры материала (`BaseColor`).

Нынешние модели расстановки уровня `ValleyOfStreams`:

```
blender -b --factory-startup --python Tools/export_polyhaven.py -- --archive DownloadResources/dandelion_01_2k.blend.zip --objects "^dandelion_01_" --lod-offset 1 --out Meshes/source/dandelion_01.glb --material-param WindWeight=1.5 --material-param TrampleWeight=0.8 --material-param TrampleBendLength=0.3 --material-param DiffuseTransmissionFactor=0.35 --material-param DiffuseTransmissionColorFactor=1,1,0.6 --material-param DiffuseTransmissionColor=BaseColor --material-param DitheredLODTransition=true
python Tools/import_gltf.py Meshes/source/dandelion_01.glb --scatter --lod-ranges 3,8
blender -b --factory-startup --python Tools/export_polyhaven.py -- --archive DownloadResources/rock_moss_set_01_2k.blend.zip --objects "^rock_moss_set_01_rock0\d$" --decimate-tris 1500,400,100 --single-sided --out Meshes/source/rock_moss_set_01.glb --material-param DitheredLODTransition=true
python Tools/import_gltf.py Meshes/source/rock_moss_set_01.glb --scatter --lod-ranges 8,20
```

Цвет просвета из той же текстуры, что базовый цвет (`DiffuseTransmissionColor=BaseColor`: одуванчики Poly Haven,
`GrassClump` из `blender_grass.py`), — импортёр умножает `BaseColorFactor` на 1 / (1 − t) (`compensate_transmission`,
строка в выводе): фото — отражённый цвет, а движок, как KHR_materials_diffuse_transmission, отражает базовый цвет × (1 − t),
и растение темнело бы на долю пропускания (у травы t = 0,4 — × 0,6). Как у Megascans (там — в `export_megascans.py`
картинками) и Two Sided Foliage в UE: отражённое — как на фото, прошедшее — t × цвет просвета. Отдельная карта просвета
не трогается.

Базовый цвет у материала `MASK` импортёр помечает `Textures.preserve_alpha_coverage` = `alphaCutoff`: мипы сохраняют покрытие
альфы ([materials.md](materials.md)), иначе пучки-карточки и лепестки тают в нескольких метрах.

Параметры движка, которых нет в glTF, — в командах (`--material-param`), у своих моделей — в сценариях:
`blender_grass.py` (ветер, пропускание, смена LOD и тон травы множителем базового цвета), `blender_cattail.py` (рогоз:
ветер, след ног, пропускание, смена LOD), `blender_camomile.py`
(ветер, пропускание), `blender_test_model.py` (смена LOD у камня). Повторный импорт их не теряет.

Трава Poly Haven `grass_medium_01` (пучки в 15–20 см, высокие — `--scale 1.7`, и подмена без архива
`Tools/blender_grass_tall.py`) удалена 2026-10-14 (решение Dimok: на лугу почти не отличалась от `GrassClump`; траву
получше добавим отдельно) — строки базы, файлы и сценарий подмены есть в истории git.

## Модели Megascans (Fab)

Растения Quixel Megascans из библиотеки Fab скачиваются архивом `.zip` в формате FBX в `DownloadResources\` (не в git;
у ассета на Fab — «Скачать», формат FBX, качество High); Unreal Launcher (Fab в лаунчере) кладёт ассет сразу распакованной
папкой (`Grass-d6846008\fbx\mid\…` — качество Mid, карты 2K, json ассета) — сценарий принимает и её: в архиве на каждый вариант и LOD — `<Ассет>_<Вар>_LOD<N>.fbx`,
карты JPG (`_BaseColor`, `_Opacity`, `_Roughness`, `_Normal` и т. д.), у растений — ещё карты карточки дальнего LOD
(`_Billboard_*`). Вариант качества Raw — только LOD0 сканов (13–52 тыс. треугольников) с картами 8K, для расстановки
не годится. `Tools/export_megascans.py` (Blender без окна) готовит из архива `.glb` для импорта с `--scatter`:

- **новый формат Fab** (загрузка лаунчера — папка `gltf/<качество>/`): glTF для движков не UE
  (`standard/*_nonUE.gltf`: узлы `SM_<ассет>_<Вар>[_LOD<N>]`, масштаб 0,01 и поворот к Y-вверх — в узлах, нормалей нет —
  сценарий сглаживает, в вершинах данные ветра `_wind` — не используются) и карты PNG по несколько в одной: `_B-O` (цвет и
  непрозрачность), `_N` (нормаль), `_ORT` (затенение, шероховатость, маска просвета), `_Billboard_B-O`, `_Billboard_N-T`
  (нормаль и маска просвета карточки). Сценарий раскладывает их в карты по одной с именами формата FBX
  (`unpack_packed_maps`) — дальше как у него. Параметры материала Unreal в extras glTF (`Normal Strength`, `Translucency
  Tint`) переносятся руками опциями `--material-param` (`NormalScale`, `DiffuseTransmissionColorFactor`); вариантов у слоя
  расстановки — не больше 8 (`--variants`);
- FBX вариантов (`--variants` — регулярное выражение по `VarA…`) импортируются, объекты называются `<--name>_<Вар>` и
  `<--name>_<Вар>_LOD<N>` (суффикс понимает импортёр); `--lod-offset k` отбрасывает LOD ниже k; поворот и масштаб FBX
  переходят в вершины, origin — у основания (у сканов он и так в точке касания земли);
- два материала простым Principled BSDF, как у Poly Haven: основной и billboard — у последнего LOD (`--billboard-lod`).
  Базовый цвет с альфой из `_Opacity` (через Round — `alphaMode: MASK`), шероховатость — в G `metallicRoughness`, нормаль —
  в соглашении OpenGL (glTF). Соглашение карты нормалей определяется по самой карте: наклоны поверхности по карте,
  прочитанной как OpenGL, — производные одной функции высоты, и их ротор мал; у карты DirectX, прочитанной как OpenGL,
  мал ротор с другим знаком (сравнение на непрозрачной части; неясный случай — ошибка, тогда `--normal-convention gl|dx`).
  У Rough Meadow Grass — OpenGL (ротор 0,066 против 0,107), у Tall Grass — тоже (0,021 против 0,051). Картинки — до `--texture-size` (2048); двусторонние;
- billboard Megascans — одна плоская карточка по силуэту (5–9 треугольников): в UE её поворачивает к камере материал,
  у нас такого материала нет, поэтому сценарий делает из неё крест — копию, повёрнутую на 90° вокруг вертикали
  (`--no-billboard-cross` — оставить одну). Карты billboard бывают не того вида, что у основного материала (у Grass
  sltiN): серая карта просвета (0,36 во всех каналах — доля, а не цвет; цветом она просвечивала белым, и дальний LOD был
  белёсым) сценарий тонирует цветом альбедо с её яркостью по текселям, а карту нормалей не касательную (синий в среднем
  0,47 — нормали почти в плоскости карточки, для камерной карточки UE) не берёт — у карточки своя нормаль. У
  основного материала обе проверки не срабатывают (просвет зелёный, синий нормалей 0,93);
- просвет и отражение — расширения glTF, которых экспортёр Blender не пишет: сценарий дописывает их в `.glb` после
  экспорта (картинка — новый bufferView в BIN). `KHR_materials_diffuse_transmission` — доля `--diffuse-transmission`
  t (0,5) и цвет из карты `_Translucency` (как Subsurface Color у Two Sided Foliage в UE; есть и у billboard);
  `KHR_materials_specular` — `specularFactor` = 2 × среднее карты `_Specular` по непрозрачной части (Specular в UE s →
  F0 = 0,08 s; у billboard своей карты нет — значение основного). У Rough Meadow Grass `Specular` ≈ 0,025 →
  `specularFactor` 0,05 (у Tall Grass — 0,07): без него отблеск неба F0 = 0,04 на тёмном скане (альбедо линейно ≈ 0,025) делал траву
  серо-чёрной;
- яркость — как у Two Sided Foliage в UE: альбедо скана — уже доля отражённого света, просвет — карта `_Translucency`
  целиком, а в glTF базовый цвет делится: отражается (1 − t), насквозь — t × цвет просвета. Поэтому сценарий
  масштабирует картинки `BaseColor` и `Translucency` в линейном пространстве на 1 / (1 − t) и 1 / t (при t = 0,5 — × 2;
  выше 1 обрезается, доля печатается: у Tall Grass — 0 % и 0,17 %, у светлой карты просвета billboard — 28 %). Без
  этого лицевая сторона была темнее скана на t, а просвет — ещё и × t: трава выходила заметно темнее превью Fab;
- цвета вершин не экспортируются (движок их не читает), параметры движка — `--material-param`, как у Poly Haven.

Grass (Megascans `sltiN`, сухая трава пучками, 6 вариантов × 4 LOD, папка из Unreal Launcher) — слой `Meadow` вдоль
ручьёв ([scatter.md](scatter.md), «Трава Megascans»):

```
blender -b --factory-startup --python Tools/export_megascans.py -- --archive DownloadResources/Grass-d6846008 --name dry_grass --out Meshes/source/dry_grass.glb --material-param WindWeight=1 --material-param TrampleBendLength=0.3 --material-param DitheredLODTransition=true
python Tools/import_gltf.py Meshes/source/dry_grass.glb --scatter --lod-ranges 4,10,20
```

Пучки 0,17–0,28 м в поперечнике и 0,30–0,61 м высотой; LOD0 — 0,5–1,7 тыс. треугольников, LOD1 и LOD2 — половина и
четверть, LOD3 — billboard крестом (6–14). Отражение — `SpecularFactor` 0,053; при × 2 обрезается 1,9 % альбедо и 14 %
просвета карточки.

Прежняя Tall Grass (`tall_grass_rbeki`, 3 варианта × 3 LOD; модели 64–66 в базе без слоя) — так же из
`DownloadResources/tall_grass_rbeki_high.zip` с `--name tall_grass` и `--lod-ranges 6,18`.

Прежняя Rough Meadow Grass (5 вариантов × 3 LOD; в базе, слоем не используется) — так же из

### Сканы Megascans: бревно, пень, грибы

Сканы (3D asset Megascans: валежник, пни, коряги, грибы) Fab отдаёт по уровню качества за загрузку — `fbx/high`, `fbx/mid`,
`fbx/low` (`<Ассет>_<id>_High|Mid|Low.fbx`, карты 4K / 2K / 1K). Скачиваются все три (формат любой): это готовые LOD
Quixel — у пня 20,6 / 4,9 / 3,3 тыс. треугольников; число треугольников уровней — в `*.json` ассета (`models`, `tier`).
`Tools/export_megascans.py` узнаёт такую папку сам: уровень качества — LOD (High — 0, Mid — 1, Low — 2), объекты файла
(`<id>_LOD0_TIER<k>_<nnn>`) — варианты (`000` → `VarA`; у группы грибов — каждый гриб), каждый вариант — в своё начало
координат (середина по горизонтали, низ — z = 0); карты — у High, сжатые до `--texture-size`. Материал непрозрачный, без
просвета (карты Translucency нет — расширение просвета не пишется); `--single-sided` — с отсечением задних граней
(замкнутые сканы). Нормаль у этих сканов — OpenGL, но проверка карты на границе уверенности: `--normal-convention gl`.

```
blender -b --factory-startup --python Tools/export_megascans.py -- --archive DownloadResources/<Ассет> --name old_stump --out Meshes/source/old_stump.glb --single-sided --normal-convention gl
python Tools/import_gltf.py Meshes/source/old_stump.glb --scatter --lod-ranges 15,40 --collision hull
```

Мелким (грибы) High не нужен: `--lod-offset 1` — LOD0 из Mid (300–1900 треугольников на гриб), LOD1 из Low, дальность —
`--lod-ranges 4`, без столкновений (`--collision none`). Валежник — `--collision hull` (бревно и пень преграждают путь),
сухое дерево — `capsule`.

### Модели без LOD: `Tools/make_lods.py`

Скан без своих LOD (обломки стволов, коряги с Fab не Megascans: один меш на 15–20 тыс. треугольников и текстуры 8K) —
`Tools/make_lods.py` (Blender без окна): файл — вариант (`<имя>_VarA` …; меши файла объединяются, начало координат —
середина по горизонтали и низ), LOD — копии с Decimate (схлопывание рёбер) на доли `--lods` от исходника (первая — LOD0),
текстуры — до `--texture-size` (2048), `--single-sided` — отсечение задних граней; материалы glTF — как есть.
`--split-objects` — каждый меш файла свой вариант (модели Poly Haven glTF с несколькими объектами: корни `pine_roots_a/b`).
Сканы Poly Haven тяжёлые (пни 41–62 тыс., корни 81 тыс. треугольников) — LOD0 тоже упрощается (доля 0,06–0,12).

```
blender -b --factory-startup --python Tools/make_lods.py -- --inputs <a>.gltf <b>.gltf --name broken_branch --out Meshes/source/broken_branch.glb --lods 0.2,0.05,0.012 --single-sided
python Tools/import_gltf.py Meshes/source/broken_branch.glb --scatter --lod-ranges 8,25 --collision none
```

## Дерево из готового меша: `Tools/tree_from_mesh.py`

Готовое дерево с Fab или Sketchfab (FBX: ствол и ветви — куски труб, листва — карточки, без LOD и данных ветра) —
`Tools/tree_from_mesh.py` (Blender без окна), бук `ValleyOfStreams`:

```
blender -b --factory-startup --python Tools/tree_from_mesh.py -- --fbx "DownloadResources/<ассет>/Beech Tree.fbx" --name Beech --out Meshes/source/beech.glb --wood Trunk --leaves Leaves --wood-drop 0,0.02,0.06
python Tools/import_gltf.py Meshes/source/beech.glb --level ValleyOfStreams --position 440,0,300 --snap-to-terrain --lod-ranges 35,90 --shadow-lod-scale 0.5
```

- **Меши** — по подстроке имени (`--wood`, `--leaves`); положение FBX (у бука — пустышка-родитель с масштабом 0,01 и
  поворотом) — в вершины, начало координат — середина основания ствола.
- **Иерархия ветвей для ветра** — по касаниям: куски древесины (острова сетки; у бука 1603 — ствол и ветви порезаны на
  отрезки) цепляются от корня к ближайшему прицепленному, допуск растёт ступенями (1 см … 50 см). Ствол — путь от корня
  по самым толстым кускам, пока кусок не тоньше `--trunk-min-radius` (6 см); ветвь первого уровня — поддерево куска,
  отходящего от ствола (у бука ствол — 5 кусков до 6 м, 31 ветвь). Данные — как у ели ([wind.md](wind.md)): ствол — доля
  высоты, ветвь — начало на стволе и вес (расстояние / наибольшее в ветви), карточка листа — ветвь ближайшей древесины,
  своё основание и доля длины (веточка и рябь).
- **LOD** — древесина без кусков тоньше `--wood-drop` (Decimate тонкую трубку не упрощает: у бука на LOD2 без этого
  оставалось 14 тыс. треугольников веточек) и Decimate на доли `--wood-ratio`; листва — доля карточек `--leaf-keep`
  (одни и те же во всех LOD), крупнее на `--leaf-scale` вокруг основания. Данные ветра LOD — у ближайшей вершины LOD0.
  У бука 70,9 / 29,0 / 13,5 тыс. треугольников (`1,0.3,0.08`, `0,0.02,0.06` м, карточки `1,0.5,0.18` × `1,1.35,2`).
- **Материалы** — по картам FBX: кора (цвет, нормаль, шероховатость), листва (цвет с альфой из карты прозрачности,
  нормаль; шероховатость — `--leaf-roughness`), нормали OpenGL; оба — `DitheredLODTransition`, `WindWeight` 1 и
  `--material-param` (ветер — одинаково у коры и листвы, иначе листья отстают от ветвей); листве — просвет
  `--transmission` (0,45) и нормаль кроны 0,5. Капсула столкновений — радиус ствола у земли (у бука 0,4 м).

## Ель

`Tools/blender_fir.py` (Blender без окна) строит ели сам, а текстуры и карточки веточек берёт из ели Poly Haven
`fir_tree_01` (CC0, архив в `DownloadResources\`). У той ели LOD0 — 0,5–4 млн треугольников, у LOD1 половина —
плотный ствол, низких LOD нет, силуэт лесной, данных для ветра нет. Сценарий строит конус, как у елей Valley, с
известной иерархией:
- **ствол** — сужающаяся труба с лёгкой кривизной и расширением у корней, от 0,3 м ниже нуля (на склоне не висит);
  развёртка цилиндрическая, повтор коры 0,8 м;
- **мутовки** — через 0,3–0,5 м (к верхушке чаще), по 4–6 ветвей со случайным азимутом. Длина ветви — по конусу
  кроны. Внизу ветви свисают (не ниже 0,4 м над землёй) и загибаются кончиком вверх, вверху смотрят вверх. Ветвь —
  тонкая труба коры;
- **хвоя** — карточки веточек Poly Haven: готовые плоскости с развёрткой в атлас хвои, 7 спрайтов. Они идут вдоль
  ветви в обе стороны под 55° и чуть вниз, к кончику короче. На кончике — веточка-кончик, наверху — вертикальный
  лидер. В LOD0 — второй ярус (`card_layers` в `LODS`): свисающие веточки под ветвью, между веточками первого и на другую
  сторону, 40° вниз (`HANGING_ANGLE`), 0,8 длины (`HANGING_LENGTH`), как у гребенчатой ели — вблизи крона без просветов
  между мутовками, снизу видна хвоя, а не голый сук. Случайные числа карточек не зависят от LOD: веточки на одних и тех же
  местах.

Варианты и LOD (дальности — `--lod-ranges 35,90`):

| Модель | Высота | LOD0 (до 35 м) | LOD1 (до 90 м) | LOD2 |
|---|---|---|---|---|
| `Fir_A` — крона почти от земли, одиночная у опушки | 20 м | 115,3 тыс. | 17,6 тыс. | 5,3 тыс. |
| `Fir_B` — крона с трети высоты, ниже сухие сучья (ель из леса) | 14 м | 54,1 тыс. | 8,5 тыс. | 3,1 тыс. |
| `Fir_C` — молодая | 7 м | 34,1 тыс. | 5,5 тыс. | 2,8 тыс. |

- **LOD0** — ствол из 12 граней, ветви из 4, все карточки (LOD1 карточек Poly Haven) в два яруса. Второй ярус и в LOD1
  стоил бы роще ещё 0,3 мс (в тенях LOD1 — уже с 17,5 м), а на смене LOD на 35 м разницы на глаз нет.
- **LOD1** — 8 и 3 грани (ветви короче метра без трубы), карточки через одну в 1,3 раза крупнее (LOD2 Poly Haven).
- **LOD2** — ствол из 5 граней и по одной карточке на ветвь, 0,8 её длины. Крупнее — и крона гуще, чем у ближних LOD:
  на смене LOD она «толстеет».

Те же модели стоят лесом — набор расстановки `Forest` по маске ели ([scatter.md](scatter.md), «Постоянные слои: лес»): до 90 м — модели (LOD0 и LOD1), дальше — импостеры, запечённые из LOD0 при загрузке.

**Материалы** — `PBRTree`: у мешей ели есть данные ветра, и импортёр ставит его сам.
- `fir/FirBark` — кора, непрозрачная;
- `fir/FirTwig` — хвоя, Masked и двусторонняя, текстуры 1024.
- Обоим в `extras` включены `DitheredLODTransition` и `WindWeight` 1. У хвои там же пропускание: 0,35, цвет —
  текстура × (1; 1; 0,6).
- **Ветер** — по схеме SpeedTree ([wind.md](wind.md)). Данные на вершину сценарий пишет сам: начало ветви на стволе,
  основание карточки хвои, веса, доля высоты.

На уровне `ValleyOfStreams` к северу от луга стоят витрина — по ели каждого варианта в 15–18 м от точки `480,12.6,300` — и роща
из 20 связанных дубликатов в пятне радиусом 22 м (центр `480,345`). Вблизи — `-Camera 474,12.2,308,-18,35`.

```
blender -b --factory-startup --python Tools/blender_fir.py -- --archive DownloadResources/fir_tree_01_2k.blend.zip --out Meshes/source/fir.glb
python Tools/import_gltf.py Meshes/source/fir.glb --level ValleyOfStreams --position 480,0,345 --snap-to-terrain --lod-ranges 35,90 --shadow-lod-scale 0.5
```

Стоимость рощи (23 ели, Release, 1920×1080):

| Точка | Без рощи | С рощей | Основная доля |
|---|---|---|---|
| Над лугом `480,17,300,22,0` | 6,54 мс | 7,56 мс | +0,66 мс — тени |
| У шаров `500,20,215,4,5` | 4,64 мс | 5,13 мс | |

Ели высокие, каждая попадает в два каскада. В тенях — LOD грубее: «Shadow LOD scale» елей 0,5 (LOD1 с 17,5 м вместо
35, у рощи LOD2 — с 45 м). Замер 2026-10-12 (Release, 1920×1080, `-nowind -noparticles`, в одной сессии попеременно, два
круга): у рощи `480,12.6,320,3,0` тени моделей 0,393 → 0,292 мс (кадр 3,60 → 3,55), в ельнике `600,22.9,132,2,20` тень
леса 0,459 → 0,335 (кадр 3,71 → 3,58), у опушки `560,18.3,105,4,60` 0,22 → 0,16; на склоне без изменений; сверх ±2
отличается 0,8–2,4 % пикселей, на глаз кадр тот же. 0,25 дешевле у рощи (0,171 мс), но крона в 20 м площе — LOD2 в тени
с 22,5 м теряет тени ярусов ветвей; «в тени не детальнее LOD1» ближнюю ель меняет заметнее (14 % пикселей), чем 0,25.
Запуск на 0,5 с дольше: шесть текстур PNG и меши.

Хвоя освещается нормалью кроны (`CrownNormalBlend` 0,6 — экстра glTF из `Tools/blender_fir.py`, [materials.md](materials.md),
«Нормаль кроны»): без неё карточки, повёрнутые от солнца, — тёмная рябь посреди освещённой кроны.

## Если что-то не так

1. **Модель вывернута наизнанку** (видна внутренняя сторона) — отрицательный масштаб объекта вместе с флипом нормалей
   в Blender; примените масштаб (Ctrl+A → Scale) и пересчитайте нормали (Mesh → Normals → Recalculate Outside).
2. **Буквы развёртки отражены** — развёртка отражена в Blender (UV-остров перевёрнут); импортёр UV не меняет.
3. **Выпуклости выглядят вмятинами** — карта нормалей в соглашении DirectX: поставьте экземпляру `NormalGreenUp = false`.
4. **Вместо модели куб** — не найден файл меша (`Meshes\models\…`): модель импортировали на другой машине, повторите
   импорт; **шахматка** — то же с текстурой.
5. **Модель не видна** — проверьте габариты в выводе скрипта и `--position` (модель под землёй), дальность последнего
   LOD и что в `LevelModels` есть строка для загружаемого уровня.
6. **Модель слишком тёмная или металл тусклый** — проверьте экспозицию ([postprocess.md](postprocess.md)) и небо,
   которое металл отражает ([sky.md](sky.md), [materials.md](materials.md)).
7. **Модель повёрнута не так, как в Blender** — поворот в базе задан вручную в другой системе: кватернион в
   `LevelModels` — в левой системе движка (из правой glTF: x и y с минусом); проверьте, не запечён ли поворот
   (предупреждение импортёра о зеркале или сдвиге осей).

## Ограничения

- Морфинга нет; скелет — один на файл (`skins[0]`), до 4 влияний на вершину.
- Один материал и одна развёртка на секцию; секция — отдельный вызов отрисовки (не больше 4 секций на LOD у моделей
  расстановки, `ScatterPass::maxSections`).
- Нет сжатия Draco / meshopt, картинок WebP / KTX2, `KHR_texture_transform`.

## Откуда подход

- Unreal Engine: импорт FBX / glTF / USD в ассеты `.uasset` и повторный импорт из исходного файла; Blender экспортирует
  в обменный формат, а не в формат движка.
- Суффикс `_LOD<N>` — соглашение импорта LOD в Unity (объекты `_LOD0`, `_LOD1` … в одном файле) и обычное имя
  LOD-мешей в проектах на UE.
- Khronos, спецификация glTF 2.0 — системы координат, узлы (translation, rotation-кватернион, scale; несколько узлов
  с одним мешем), касательные (bitangent = cross(normal, tangent.xyz) · w), материал metallic-roughness, материал
  по умолчанию.
- Unreal Engine: FTransform (Translation, Rotation, Scale3D) у актора, один ассет Static Mesh на много акторов.
