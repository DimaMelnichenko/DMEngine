# Удалённое управление движком

Запущенный движок можно вести командами извне: переставить камеру, снять кадр, замерить время GPU, поменять любое
свойство из окон GUI, нажать горячую клавишу, выйти. Так одна сессия заменяет серию запусков `Tools/run.ps1`. Раньше на
каждый кадр уходили ~4 с инициализации и 8 с ожидания, а снимок был копией экрана с рамкой окна и водяным знаком.
Устроено как консольные команды UE (`BugItGo`, `HighResShot`, `stat gpu`) и свойства объектов в Remote Control API.
Только локально: именованный канал вместо HTTP.

## Как запустить

```
python Tools/engine.py start [--config Debug|Release] [--camera x,y,z,pitch,yaw] [--level имя] [--nogui] [--mouse] [--nowind] [--noparticles] [--freezetime] [--nocolorgrading] [--preset имя] [--gpu-validation] [--stableclocks]
python Tools/engine.py camera 567,58.1,212,8,35
python Tools/engine.py screenshot кадр.png
python Tools/engine.py stat gpu 3
python Tools/engine.py run сценарий.txt
python Tools/engine.py stop
```

- `start` запускает `cmake-build-cli-<config>\DMEngine.exe` из корня проекта (по умолчанию Release) с параметрами
  `-remote`, `-nomouse` (без `--mouse`: камера не следует за мышью) и `-resolution 1920x1080` — окно с заголовком
  1920 × 1080, снимки и замеры сравнимы между запусками и с прежними цифрами (`--resolution desktop` — окно без рамки
  на весь монитор, как у движка без параметра; любое `ШxВ` — своё окно). Кадры с одной точки совпадают до пикселя, если
  не движется трава: `--nowind` (параметр движка `-nowind`) или `set "Wind/Enabled" false` ([wind.md](wind.md)), нет
  частиц: `--noparticles` (`-noparticles`, [particles.md](particles.md)) и стоит рябь воды: `--freezetime` (`-freezetime`:
  время игры на нуле — иначе снимок делается в разный момент игры). `--nocolorgrading` (`-nocolorgrading`, в сессии
  `set "Post process/Color grading/Enabled" false`) — без цветокоррекции уровня, только кривая тонмаппинга: снимки
  сравнимы с эталоном, как бы её ни настроили ([postprocess.md](postprocess.md)). Сверка кадров и времени GPU с эталоном одной
  командой — `Tools/check_frames.py` ([d3d12.md](d3d12.md) §4). `--gpu-validation` (`-gpuvalidation`) —
  GPU-based validation ([d3d12.md](d3d12.md) §4), только в Debug: без `--config` запускает Debug, с `--config Release` —
  ошибка (Release без слоя проверки шёл бы молча). `--stableclocks` (`-stableclocks`, `StableClocks=true` в `settings.ini`) —
  закреплённая частота GPU на время жизни устройства (`SetStablePowerState`, как «Lock to stable clocks» в PIX): «GPU
  average» не скачет от разгона, питания и нагрева, мс больше обычных (базовая частота); нужен режим разработчика Windows —
  без него частота не закрепляется, в логе строка «GPU clocks are not locked», а у «GPU average» нет пометки
  «stable clocks». Затем ждёт, пока движок откроет канал, то есть конца инициализации, и
  первого кадра (`wait 1`).
- **Ответ — не дольше 60 с** (`python Tools/engine.py --timeout 120 <команда>` — своё время; у `stat gpu N` — ещё N, у
  `pix` — 300): не ответил — главный цикл движка стоит. Скрипт печатает строки «Frame watchdog» из `log.txt` (сторож
  кадра `FrameWatchdog`: шаг кадра дольше 10 с, последняя метка, ход GPU — [d3d12.md](d3d12.md) §4) и выходит с кодом 2,
  не закрывая канал; `start` и `stop` такой движок закрывают принудительно (`stop` — и тот, что не вышел за 20 с).
- Одна команда — `python Tools/engine.py <команда …>`: печатает ответ, при `error` код выхода 1. Слова с пробелами — в
  кавычках, как в командной строке.
- `run` — команды из файла по строке за одно подключение; `#` — комментарий. Каждая строка печатается с `>`, за ней ответ.
- `stop` — `quit`, ожидание выхода процесса, затем из `log.txt` ошибки, время инициализации и строки «GPU average» и «CPU average», как
  печатает `run.ps1`. Выход штатный: `Engine::beforeExit` выполняется, лог дописан.
- `Tools/run.ps1` (PowerShell, без Python) — тот же канал на один запуск: `-remote`, ожидание конца инициализации и
  `-Seconds`, клавиши — `key 0x..` (скан-код в hex: одиночная цифра у `key` — клавиша, а не скан-код), снимок —
  `screenshot` (задний буфер, `gui` без `-NoGui`), выход — `quit`; принудительно — только если движок не вышел за 30 с
  или не ответил на команду за 60 с (тогда — строки «Frame watchdog» из лога); `-GpuValidation` — Debug с GPU-based
  validation.

Путь снимка клиент переводит в абсолютный от текущей папки. У самого движка рабочая папка — корень проекта.

## Команды

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `camera [x,y,z[,pitch,yaw]]` | телепорт камеры (как `BugItGo`): положение и поворот в градусах, pitch > 0 — вниз; без поворота — прежний. Без аргументов — текущая камера; её же показывает окно GUI «Camera»: положение, вектор направления, pitch / yaw и строку `x,y,z,pitch,yaw` с кнопкой копирования — по скриншоту с окнами камеру ставят этой командой. Это смена плана: экспозиция несколько кадров адаптируется сразу, а не 1–2 с |
| `screenshot файл.png [gui] [кадров]` | задний буфер в PNG (или JPG по расширению) — ровно то, что рисует движок, без рамки окна. Без `gui` — до окон ImGui. Снимок ждёт, пока кадр устоится после смены плана (10 кадров). С числом кадров — серия подряд, по кадру на снимок: `файл_00.png`, `файл_01.png`… |
| `stat gpu [секунды]` | среднее время GPU кадра и проходов за столько секунд (по умолчанию 3), после того как кадр устоится — строкой, как «GPU average» в `log.txt` |
| `stat cpu [секунды]` | то же для CPU, строкой, как «CPU average» в `log.txt`: `frame` — работа кадра от конца ожидания swap chain до конца записи команд; отдельно `Wait for frame` (ожидание swap chain — GPU не успевает) и `Submit and present` (прошлого кадра); шаги — `Update: <объект>`, `Compute: <объект>`, `Collect main view` и `Collect shadow views` (сбор мешей с видов), `Build commands` и `Build shadow commands` (раскладка с сортировкой), запись команд по объектам (`<объект>`, `Prepass: <объект>`, `Shadow: <объект>`), `Post process`, `GUI Rendering` (прошлого кадра) — все счётчики «… ms» окна «Statistic»; одноимённые за кадр складываются |
| `list [окно/подокно]` | окна свойств GUI, их подокна (`имя/`), свойства со значениями и единицей (`Far border = 45 m`) и кнопки окна (`[имя]`) |
| `get окно/свойство` | значение свойства |
| `set окно/свойство значение` | новое значение свойства — так же, как ползунок в GUI: объекты читают свойства каждый кадр |
| `press "окно/кнопка"` | нажать кнопку окна, как в Details (с отменой — правка истории): `press "Lights/Add point light"`, `press "Lights/2: Point light (point)/Delete"`; ответ — имя правки ([gui.md](gui.md)) |
| `key клавиша` | нажатие горячей клавиши (буква, цифра или скан-код `DIK_*`, как в DirectInput): `G`, `Q`, `1`, `3`, `4`… |
| `gui on\|off` | окна редактора, как клавиша G |
| `action "имя"` | действие меню File редактора: `"Save level"` — правки окон в базу, `"Exit"` ([gui.md](gui.md)) |
| `preset [имя \| level \| save имя]` | пресеты окружения уровня (время суток, небо, постобработка, ветер, туман, облака): без аргументов — список (`*` — активный, `locked` — «Save level» его не пишет), имя — выбрать на лету (`level` — строки уровня), `save` — окна как новый пресет ([gui.md](gui.md), «Пресеты окружения») |
| `undo` / `redo` | отменить / повторить последнюю правку редактора, как Ctrl+Z / Ctrl+Y; ответ — имя правки ([gui.md](gui.md), «Отмена правок»; сам `set` в историю не попадает) |
| `pick x y` | выбрать под точкой окна (пиксели), как клик во вьюпорте: в режиме «Stream curves» — точку кривой русла, затем значок источника света или эмиттера частиц, иначе экземпляр модели; ответ — `Stream 7, point 3`, имя экземпляра или `nothing` ([gui.md](gui.md)) |
| `brush x y [x y …] [shift] [ctrl]` | мазок кисти подокна «Paint» окна террейна через точки окна (пиксели), как мышью с зажатой ЛКМ в режиме «Terrain paint»: луч к рельефу, промежуточные касания, правка в истории (`undo`); ответ — цель и концы мазка в мире ([gui.md](gui.md)) |
| `toggle "имя"` | переключатель меню View (`Stream curves`, `Wireframe`…); ответ — `on` / `off` |
| `stream move x,z` / `insert` / `delete` / `falloff м` | правка выбранной точки кривой русла, как гизмо (с мягким выделением), Insert, Delete и ползунок «Falloff»; русла перестраиваются в следующем кадре ([water.md](water.md), «Кривые русел») |
| `pix [файл.wpix] [кадров]` | захват PIX следующих кадров (движок с `-pix`, `engine.py start --pix`), после того как кадр устоится; ответ — путь, когда файл записан; по умолчанию `captures\<дата_время>.wpix`. Разбор — `Tools/pix_events.py` ([d3d12.md](d3d12.md) §4) |
| `select "окно"` | выбрать окно свойств в Outliner — Details показывает его (снимки редактора сценарием: `screenshot файл.png gui`) |
| `wait кадров` | пропустить столько кадров |
| `water discharge файл.dds` | расход воды ячеек симуляции, м³/с, в DDS `R32_FLOAT` (`WaterSimulation::exportDischarge`) — для проверки |
| `water state префикс` | текстура воды для шейдеров (`SLOT_WATER`) в DDS `R32_FLOAT`: `_depth` — глубина, м, `_vx`, `_vz` — течение по X и Z мира, м/с (`WaterSimulation::exportState`; строка 0 — дальний край по z) — проверка течения ручьёв и озёр ([water.md](water.md), «Течение ручьёв и озёр»); в режиме `static` ещё детальная вода у русел одним растром 0,25 м на весь мир (−1e9 — плитки нет): `_detail_level` — уровень поверхности, м, `_detail_depth`, `_detail_vx`, `_detail_vz` и вход её течения из конвейера — `_detail_u0x`, `_detail_u0z` (скорость по Маннингу `u₀`), `_detail_radius` (`R` русла) ([water.md](water.md), «Детальная вода у русел»), и поле пены — `_foam` (сетка 1 м), `_detail_foam` (детальная, 0 — плитки нет) ([water.md](water.md), «Материал», «Пена») |
| `terrain paint цель x z радиус value\|step\|unstep\|erase значение [falloff]` | мазок кисти поверх правил слоёв в точке мира: цель — `"layer N"` или `wetness` (сетка 0,25 м) или имя маски (`mask_forest_spruce`, 1 м); `value` — итог к значению, `step` / `unstep` — поправка ± значение, `erase` — к правилам; `terrain paint clear цель`, `terrain paint list`, `terrain paint probe цель x z` — правило, поправка и итог в точке ([terrain.md](terrain.md), «Ручная правка слоёв и масок») |
| `terrain hydrology префикс` | русла и вода конвейера рельефа в DDS `R32_FLOAT`: `_lowering` — опускание ложа, `_level` — уровень ручьёв, `_lake` — уровень озёр, `_detail` — детальная земля у русел, 4096², −1e9 — плиток нет ([water.md](water.md), [terrain.md](terrain.md)) |
| `passes` | список проходов следующего кадра в `log.txt` (`DMD3D::logPasses`): имя, цели с размером, что читает и пишет — по объявлениям `PassDesc` (`D3D/GpuPass.h`); compute-проходы помечены `compute` |
| `timestep [секунды\|off]` | фиксированный шаг времени кадра, как `-UseFixedTimeStep` в UE: камера, экспозиция, частицы и время суток идут шагами, сколько бы кадр ни длился. Нужен сериям кадров: запись снимков не сбивает ход времени |
| `quit` | штатный выход |

Те же команды набираются в консоли редактора (окно Output, вкладка Console, клавиша `` ` ``): ответ — в окне, Tab
дополняет имена команд и пути свойств.

Значения свойств: `true` / `false` (или `1` / `0`, `on` / `off`), числа, векторы `x,y,z`. Путь — имена окон, как в GUI:
`set "CDLOD terrain/Far blend" 60,150`, `set "Camera/Field of view" 30`, `list Lights`, `get "Meadow/0: GrassClump + 3/Cast shadow"`.

## Сценарий: серия кадров за один запуск

```
# сценарий.txt
camera 567,58.1,212,8,35
screenshot луг.png
stat gpu 3
camera 512,160,150,30,0
screenshot обзор.png
stat gpu 3
set "CDLOD terrain/Far blend" 60,150
screenshot обзор_60.png
```

```
python Tools/engine.py start --nogui
python Tools/engine.py run сценарий.txt
python Tools/engine.py stop
```

Такая сессия — три снимка и два замера — идёт ~12 с. Замер после смены камеры начинается, только когда кадр устоится.

## Серия кадров: проверка на мерцание и скачки

Чтобы увидеть, что меняется от кадра к кадру (скачки освещения, дрожание теней), нужна серия подряд с ровным шагом
времени:

```
timestep 0.0166667
set "Lights/Sun position/Time of day" 6.2
set "Lights/Sun position/Time scale" 3600
camera 567,58.1,212,8,35
screenshot рассвет.png 24
timestep off
```

При 3600 кадр — игровая минута. Дальше средняя яркость кадров серии и её участков показывает ступеньки, а пиксели,
которые светлеют и тут же темнеют, — мерцание. Так была найдена и проверена ступенька освещения окружением раз в 8
кадров (docs/sky.md). Чтобы экспозиция не смешивалась с измеряемым, её ставят вручную:
`set "Post process/Metering mode" 0` (номер в списке: 0 — Manual, 1 — Auto histogram).

## Как устроено

- **Канал** `\\.\pipe\DMEngine` открывает `RemoteControlServer` (`src/Engine/Console/`), если движок запущен с
  `-remote`. Один экземпляр: второй движок с `-remote` канал не получит — строка в логе. Сетевые клиенты отклоняются
  (`PIPE_REJECT_REMOTE_CLIENTS`); по правам канала по умолчанию писать в него может только сам пользователь.
- **Протокол** — строки UTF-8: команда до `\n`, ответ — строки текста, последняя `ok` или `error: …`. Следующую
  команду соединения сервер читает только после ответа на предыдущую, поэтому сценарий выполняется строго по порядку.
- **Потоки.** Канал читает свой поток и кладёт команду в очередь; выполняет её главный поток в начале кадра
  (`Engine::tick`). Поэтому камера, свойства и клавиши действуют уже в этом кадре, а гонок с отрисовкой нет.
  Долгая команда держит ответ (`ConsoleReply`) и завершает его в своей точке кадра: снимок — перед окнами ImGui или после
  них и до `Present` (после него содержимое заднего буфера не определено); замер — когда истечёт время
  (`Renderer::measureGpu`). `wait` — задача на кадры (`ConsoleCommands::addFrameTask`).
- **Выход.** `quit` поднимает флаг, `DMSystem` выходит, как по Esc. `beforeExit` останавливает сервер: ответ на `quit`
  поток канала дописывает, ожидание подключения и чтения прерывает событием остановки (overlapped I/O).
- **Смена плана** (`Renderer::cameraCut` → `PostProcess::cameraCut`): четыре кадра адаптация экспозиции идёт с
  большим шагом времени и доходит до цели за кадр, как сброс Eye Adaptation у вида с `bCameraCut` в UE. Первые кадры
  после запуска — тоже смена плана.

## Как добавить команду

Команду регистрирует её подсистема, как консольные команды модулей UE: движок — свои (проходы, камера, снимок, PIX, шаг
времени, замер, клавиши, окна ImGui, выход — `Engine::registerCommands`, `EngineCommands.cpp`), редактор —
`GUI::registerCommands` (`action`, `select`, `toggle`, `undo`, `redo` и свойства окон — `registerPropertyCommands`),
вьюпорт — `Viewport::registerCommands` (`pick`, `brush`, `stream`), подсистемы сцены — `registerSceneCommands`
(`Scene/SceneCommands.cpp`: `terrain`, `water`; разбор аргументов там, дело — у подсистемы). Регистрацию всех вызывает
`Engine::initialize`, затем отдаёт имена дополнению консоли редактора:

```cpp
m_console.registerCommand( "имя", "<аргументы> - что делает", [this]( const std::vector<std::string>& args,
                                                                    const ConsoleReplyPtr& reply )
{
	if( args.empty() )
		return reply->error( "имя: expected ..." );
	reply->line( "текст ответа" );
	reply->ok();
} );
```

Ответ обязателен: `ok` или `error` ровно один раз. Если его не дать, при удалении `ConsoleReply` клиент получит
`error: command did not reply`. Команда на несколько кадров сохраняет `reply` и завершает его позже. Свойство, которое
уже есть в окне GUI, отдельной команды не требует — его видят `list` / `get` / `set`.

## Если что-то не так

1. **`error: an engine with -remote is already running`** — движок из прошлой сессии не закрыт: `python Tools/engine.py stop`.
2. **`start` ждёт и выходит с ошибкой инициализации** — причина в выведенных строках `log.txt`, как у `run.ps1`.
3. **Кадр с другой экспозицией** — снимок сделан раньше, чем устоялась адаптация. Перед `screenshot` должна быть
   `camera` (смена плана); при медленной смене света (время суток) добавьте `wait`.
4. **`key` отвечает `nothing is bound`** — на эту клавишу нет обработчика в `Engine::bindingKeys`.
