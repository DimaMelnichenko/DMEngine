# Удалённое управление движком

Запущенный движок можно вести командами извне: переставить камеру, снять кадр, замерить время GPU, поменять любое
свойство из окон GUI, нажать горячую клавишу, выйти. Так одна сессия заменяет серию запусков `Tools/run.ps1`. Раньше на
каждый кадр уходили ~4 с инициализации и 8 с ожидания, а снимок был копией экрана с рамкой окна и водяным знаком.
Устроено как консольные команды UE (`BugItGo`, `HighResShot`, `stat gpu`) и свойства объектов в Remote Control API.
Только локально: именованный канал вместо HTTP.

## Как запустить

```
python Tools/engine.py start [--config Release] [--camera x,y,z,pitch,yaw] [--level имя] [--nogui] [--mouse] [--nowind] [--noparticles]
python Tools/engine.py camera 567,58.1,212,8,35
python Tools/engine.py screenshot кадр.png
python Tools/engine.py stat gpu 3
python Tools/engine.py run сценарий.txt
python Tools/engine.py stop
```

- `start` запускает `cmake-build-cli-<config>\DMEngine.exe` из корня проекта (по умолчанию Release) с параметрами
  `-remote` и `-nomouse` (без `--mouse`: камера не следует за мышью). Кадры с одной точки совпадают до пикселя, если
  не движется трава: `--nowind` (параметр движка `-nowind`) или `set "Wind/Enabled" false` ([wind.md](wind.md)), и нет
  частиц: `--noparticles` (`-noparticles`, [particles.md](particles.md)). Затем ждёт,
  пока движок откроет канал, то есть конца инициализации.
- Одна команда — `python Tools/engine.py <команда …>`: печатает ответ, при `error` код выхода 1. Слова с пробелами — в
  кавычках, как в командной строке.
- `run` — команды из файла по строке за одно подключение; `#` — комментарий. Каждая строка печатается с `>`, за ней ответ.
- `stop` — `quit`, ожидание выхода процесса, затем из `log.txt` ошибки, время инициализации и строки «GPU average», как
  печатает `run.ps1`. Выход штатный: `DMGraphics::beforeExit` выполняется, лог дописан.

Путь снимка клиент переводит в абсолютный от текущей папки. У самого движка рабочая папка — корень проекта.

## Команды

| Команда | Что делает |
|---|---|
| `help` | список команд |
| `camera [x,y,z[,pitch,yaw]]` | телепорт камеры (как `BugItGo`): положение и поворот в градусах, pitch > 0 — вниз; без поворота — прежний. Без аргументов — текущая камера; её же показывает окно GUI «Camera»: положение, вектор направления, pitch / yaw и строку `x,y,z,pitch,yaw` с кнопкой копирования — по скриншоту с окнами камеру ставят этой командой. Это смена плана: экспозиция несколько кадров адаптируется сразу, а не 1–2 с |
| `screenshot файл.png [gui] [кадров]` | задний буфер в PNG (или JPG по расширению) — ровно то, что рисует движок, без рамки окна. Без `gui` — до окон ImGui. Снимок ждёт, пока кадр устоится после смены плана (10 кадров). С числом кадров — серия подряд, по кадру на снимок: `файл_00.png`, `файл_01.png`… |
| `stat gpu [секунды]` | среднее время GPU кадра и проходов за столько секунд (по умолчанию 3), после того как кадр устоится — строкой, как «GPU average» в `log.txt` |
| `list [окно/подокно]` | окна свойств GUI, их подокна (`имя/`) и свойства со значениями |
| `get окно/свойство` | значение свойства |
| `set окно/свойство значение` | новое значение свойства — так же, как ползунок в GUI: объекты читают свойства каждый кадр |
| `key клавиша` | нажатие горячей клавиши (буква, цифра или скан-код DirectInput): `G`, `Q`, `1`, `3`, `4`… |
| `gui on\|off` | окна редактора, как клавиша G |
| `action "имя"` | действие меню File редактора: `"Save level"` — правки окон в базу, `"Exit"` ([gui.md](gui.md)) |
| `pick x y` | выбрать под точкой окна (пиксели), как клик во вьюпорте: в режиме «Stream curves» — точку кривой русла, иначе экземпляр модели; ответ — `Stream 7, point 3`, имя экземпляра или `nothing` ([gui.md](gui.md)) |
| `toggle "имя"` | переключатель меню View (`Stream curves`, `Wireframe`…); ответ — `on` / `off` |
| `stream move x,z` / `insert` / `delete` / `falloff м` | правка выбранной точки кривой русла, как гизмо (с мягким выделением), Insert, Delete и ползунок «Falloff»; русла перестраиваются в следующем кадре ([water.md](water.md), «Кривые русел») |
| `select "окно"` | выбрать окно свойств в Outliner — Details показывает его (снимки редактора сценарием: `screenshot файл.png gui`) |
| `wait кадров` | пропустить столько кадров |
| `water discharge файл.dds` | расход воды ячеек симуляции, м³/с, в DDS `R32_FLOAT` (`WaterSimulation::exportDischarge`) — для проверки |
| `water state префикс` | текстура воды для шейдеров (`SLOT_WATER`) в DDS `R32_FLOAT`: `_depth` — глубина, м, `_vx`, `_vz` — течение по X и Z мира, м/с (`WaterSimulation::exportState`; строка 0 — дальний край по z) — проверка течения озёр ([water.md](water.md), «Течение озёр») |
| `terrain hydrology префикс` | русла и вода конвейера рельефа в DDS `R32_FLOAT`: `_lowering` — опускание ложа, `_level` — уровень ручьёв, `_lake` — уровень озёр, `_detail` — детальная земля у русел, 4096², −1e9 — плиток нет ([water.md](water.md), [terrain.md](terrain.md)) |
| `passes` | список проходов следующего кадра в `log.txt` (`DMD3D::logPasses`): имя, цели с размером, что читает и пишет — по объявлениям `PassDesc` (`D3D/GpuPass.h`); compute-проходы помечены `compute` |
| `timestep [секунды\|off]` | фиксированный шаг времени кадра, как `-UseFixedTimeStep` в UE: камера, экспозиция, частицы и время суток идут шагами, сколько бы кадр ни длился. Нужен сериям кадров: запись снимков не сбивает ход времени |
| `quit` | штатный выход |

Те же команды набираются в консоли редактора (окно Output, вкладка Console, клавиша `` ` ``): ответ — в окне, Tab
дополняет имена команд и пути свойств.

Значения свойств: `true` / `false` (или `1` / `0`, `on` / `off`), числа, векторы `x,y,z`. Путь — имена окон, как в GUI:
`set "CDLOD terrain/Far blend start" 60`, `list Lights`, `get "Meadow/0: GrassClump + 3/Cast shadow"`.

## Сценарий: серия кадров за один запуск

```
# сценарий.txt
camera 567,58.1,212,8,35
screenshot луг.png
stat gpu 3
camera 512,160,150,30,0
screenshot обзор.png
stat gpu 3
set "CDLOD terrain/Far blend start" 60
screenshot обзор_60.png
```

```
python Tools/engine.py start --nogui
python Tools/engine.py run сценарий.txt
python Tools/engine.py stop
```

Такая сессия — три снимка и два замера — идёт ~12 с. Замер после смены камеры начинается, только когда кадр устоится.

## Серия кадров: проверка на мерцание и скачки

Чтобы увидеть, что меняется от кадра к кадру (скачки освещения, дрожание теней), нужна серия подряд с ровным шагом
времени:

```
timestep 0.0166667
set "Lights/Sun position/Time of day (h)" 6.2
set "Lights/Sun position/Time scale" 3600
camera 567,58.1,212,8,35
screenshot рассвет.png 24
timestep off
```

При 3600 кадр — игровая минута. Дальше средняя яркость кадров серии и её участков показывает ступеньки, а пиксели,
которые светлеют и тут же темнеют, — мерцание. Так была найдена и проверена ступенька освещения окружением раз в 8
кадров (docs/sky.md). Чтобы экспозиция не смешивалась с измеряемым, её ставят вручную:
`set "Post process/Metering mode (0 manual, 1 auto)" 0`.

## Как устроено

- **Канал** `\\.\pipe\DMEngine` открывает `RemoteControlServer` (`src/Engine/Console/`), если движок запущен с
  `-remote`. Один экземпляр: второй движок с `-remote` канал не получит — строка в логе. Сетевые клиенты отклоняются
  (`PIPE_REJECT_REMOTE_CLIENTS`); по правам канала по умолчанию писать в него может только сам пользователь.
- **Протокол** — строки UTF-8: команда до `\n`, ответ — строки текста, последняя `ok` или `error: …`. Следующую
  команду соединения сервер читает только после ответа на предыдущую, поэтому сценарий выполняется строго по порядку.
- **Потоки.** Канал читает свой поток и кладёт команду в очередь; выполняет её главный поток в начале кадра
  (`DMGraphics::Frame`). Поэтому камера, свойства и клавиши действуют уже в этом кадре, а гонок с отрисовкой нет.
  Долгая команда держит ответ (`ConsoleReply`) и завершает его в своей точке кадра: снимок — перед окнами ImGui или после
  них и до `Present` (после него содержимое заднего буфера не определено); замер — когда истечёт время
  (`Renderer::measureGpu`). `wait` — задача на кадры (`ConsoleCommands::addFrameTask`).
- **Выход.** `quit` поднимает флаг, `DMSystem` выходит, как по Esc. `beforeExit` останавливает сервер: ответ на `quit`
  поток канала дописывает, ожидание подключения и чтения прерывает событием остановки (overlapped I/O).
- **Смена плана** (`Renderer::cameraCut` → `PostProcess::cameraCut`): четыре кадра адаптация экспозиции идёт с
  большим шагом времени и доходит до цели за кадр, как сброс Eye Adaptation у вида с `bCameraCut` в UE. Первые кадры
  после запуска — тоже смена плана.

## Как добавить команду

Обработчик — в `DMGraphics::registerCommands` (или рядом с подсистемой, как `registerPropertyCommands`):

```cpp
m_console.registerCommand( "имя", "<аргументы> - что делает", [this]( const std::vector<std::string>& args,
                                                                    const ConsoleReplyPtr& reply )
{
	if( args.empty() )
		return reply->error( "имя: expected ..." );
	reply->line( "текст ответа" );
	reply->ok();
} );
```

Ответ обязателен: `ok` или `error` ровно один раз. Если его не дать, при удалении `ConsoleReply` клиент получит
`error: command did not reply`. Команда на несколько кадров сохраняет `reply` и завершает его позже. Свойство, которое
уже есть в окне GUI, отдельной команды не требует — его видят `list` / `get` / `set`.

## Если что-то не так

1. **`error: an engine with -remote is already running`** — движок из прошлой сессии не закрыт: `python Tools/engine.py stop`.
2. **`start` ждёт и выходит с ошибкой инициализации** — причина в выведенных строках `log.txt`, как у `run.ps1`.
3. **Кадр с другой экспозицией** — снимок сделан раньше, чем устоялась адаптация. Перед `screenshot` должна быть
   `camera` (смена плана); при медленной смене света (время суток) добавьте `wait`.
4. **`key` отвечает `nothing is bound`** — на эту клавишу нет обработчика в `DMGraphics::bindingKeys`.
