# Тесты логики на CPU

Поведение зверей, распорядок жителей, навигацию и столкновения картинкой не проверишь: снимки контрольных камер
(`Tools/check_frames.py`, [d3d12.md](d3d12.md) §4) ловят то, что видно в кадре, а логика без кадра — тестами. Тесты —
консольный exe `DMEngineTests` на [doctest](https://github.com/doctest/doctest) против ядра движка `DMCore` — логики без
устройства. Весь набор идёт доли секунды (Release ~0,1 с, Debug ~0,3 с) и собирается вместе с движком.

## Как запускать

```
Tools\test.cmd                         (release; из Git Bash: cmd //c "Tools\test.cmd release")
Tools\test.cmd debug
Tools\test.cmd release -tc=WalkMode*   (только тесты, чьё имя подходит под шаблон)
```

Скрипт собирает конфигурацию (`Tools\build.cmd`: движок, ядро и тесты) и запускает `DMEngineTests.exe` в каталоге сборки
`cmake-build-cli-<конфигурация>`; код выхода — результат (0 — все прошли). Остальные параметры уходят doctest как есть:
`-tc=шаблон` — тесты по имени, `-tce=шаблон` — кроме них, `-s` — печатать и прошедшие проверки, `-d` — время каждого теста,
`--help` — все. Из CLion — цель `DMEngineTests`; `ctest` в каталоге сборки — тоже он.

Рабочая папка — каталог сборки: лог ядра (`LOG`) пишется в его `log.txt` и не затирает `log.txt` движка в корне проекта.
Временные файлы (WAV для `AudioClip`) тест пишет в системный временный каталог и удаляет сам.

Упавшая проверка печатает файл, строку, выражение и значения:

```
tests\test_terrain.cpp(69): ERROR: CHECK( terrain.metres( 31, 31 ) == doctest::Approx( 20.0f ).epsilon( 0.01 ) ) is NOT correct!
  values: CHECK( 0 == Approx( 20 ) )
```

## Ядро DMCore

Как модули Core и Engine в UE: статическая библиотека `DMCore` (`CMakeLists.txt`) — то, что работает без устройства D3D12,
ImGui, DirectXTex и базы: свойства и описания полей (`Property`, `PropertyContainer`, `LevelSettings.cpp`), лог, таймер,
время суток (`SunPosition`), правки рельефа (`TerrainEdits`), русла и вода на CPU (`TerrainHydrology`), ветер (`Wind`),
звук без вывода (`AudioMixer`, `AudioSynth`, `AudioClip`; вывод XAudio2 — в движке), камера, ходьба и ввод (`DMCamera`,
`WalkMode`, `Input`), мир симуляции на EnTT и мировые часы (`World`, `WorldClock`, системы — [simulation.md](simulation.md)), столкновения на Jolt
(`PhysicsWorld` — [physics.md](physics.md)). Её собирают движок и тесты. Файлы лежат на своих местах в `src/` — ядро задаётся списком библиотеки,
а не каталогом. Общие include-пути, defines и флаги компилятора движка, ядра и тестов — одна цель `DMEngineSettings`.

**Граница проверяется каждой сборкой.** Тестовый exe берёт ядро целиком (`/WHOLEARCHIVE:DMCore`), поэтому ссылка любого
файла ядра на устройство, ImGui или базу — ошибка линковки `DMEngineTests` (`LNK2019 … DMD3D::instance`), даже если тесты
этот код не вызывают. Новая логика без устройства — слой симуляции, мировые часы, навигация, столкновения — пишется в ядро
(или в библиотеку над ним), рендер о ней не знает: объект сцены берёт у неё состояние и отдаёт меши.

Если логику нужно проверить, а она живёт в классе с устройством, — вынести её чистой функцией или структурой без
устройства, класс зовёт её. Так сделано:

- ключи сортировки команд отрисовки — `Graphics/DrawSortKey.h` (`opaqueSortKey`, `transparentSortKey`, `shadowSortKey`,
  `customSortKey`), их зовёт `Renderer`;
- шаг пересадки экземпляра модели на новую землю — `Scene/Model/ModelReseat.h` (`reseatPosition`), его зовёт
  `ModelInstances::reseat`;
- параметры ветра для шейдеров и звука — `Scene/Wind/WindParameters.h`: `Wind.h` не тянет буферы констант рендера.

Заголовок можно включать и без переноса в ядро, если в нём нет ссылок на символы движка (`inline`-функции, структуры).

## Как добавить тест

Файл `tests/test_<подсистема>.cpp` — CMake подхватит его сам (`file(GLOB … CONFIGURE_DEPENDS)`, папка сборки
перенастроится при следующей сборке):

```cpp
#include <doctest/doctest.h>
#include "Light\SunPosition.h"

TEST_CASE( "SunPosition: the sun is below the horizon at midnight" )
{
	SunPosition::Settings settings;
	settings.latitude = 45.0f;
	settings.timeOfDay = 0.0f;
	CHECK( SunPosition::compute( settings ).elevation < 0.0f );
}
```

- `CHECK` — проверка продолжает тест, `REQUIRE` — останавливает (когда дальше без значения нельзя: указатель, размер);
  числа с плавающей точкой — `doctest::Approx( значение ).epsilon( доля )`.
- Ожидания в нынешних тестах — из независимого источника (формула, известное событие: полнолуние по календарю), а не
  «сколько выдал код»; откуда число — в комментарии рядом.
- Зависимость от рельефа — подделка интерфейса `TerrainHeightSource` (`FakeTerrain` в `tests/fake_terrain.h`: высота
  функцией); клавиши — `Input::setKeyDown( DIK_W, true )` и `Input::instance().Frame()`.
- Рельеф для русел и воды — маленькая карта (128 × 128) с понятной формой: V-долина (`test_terrain.cpp`).
- Имена тестов — по-английски, комментарии — по-русски.

## Ограничения

- Заголовки ядра тянут `d3d12.h` через `Graphics/Common/DirectX.h` (символов D3D в ядре нет — граница по линковке
  держится, но по заголовкам связь есть): разделить `DirectX.h` на математику и устройство — `TODO.md`, «Архитектура».
- Шейдеры и всё, что на GPU (эрозия, маски, расстановка, течение), тестами не покрыты — их проверяют снимки контрольных
  камер; тесты compute-шейдеров на WARP — `TODO.md`, «Решить или проверить».
- `Input` — синглтон с Raw Input: тесты ходьбы меняют его общее состояние (клавиши отпускаются в конце теста).
