# Материалы и PBR

Материал определяет, каким шейдером и с какими параметрами рисуется LOD модели. Основной материал моделей — `PBR`:
физически корректное освещение по схеме metallic/roughness. Та же модель лежит в основе материала glTF 2.0 и Default Lit
в Unreal Engine, поэтому параметры названы как в glTF и модели из Blender переносятся без пересчёта.

Возможности:

- базовый цвет, металличность, шероховатость, карта нормалей, затенение окружающего света и свечение — каждое как
  текстура, множитель или то и другое;
- прямой свет по Cook-Torrance GGX от источников `Scene\Lights.ini` и окружающий свет полусферой неба и земли;
- экземпляры материала: у каждой модели свои значения параметров поверх умолчаний материала;
- ползунки и выбор цвета в GUI на лету;
- инстансный вариант `PBRInstance` для расстановки (камешки, ромашки).

## Понятия

**Материал** — строка `Materials`. Колонка `class` выбирает класс шейдера на C++ (`PBR` → `PBRMaterial`), шейдеры
стадий берутся из `MaterialShaderLink` → `Shader` (файл, стадия, defines), список параметров — из
`MaterialParameterDef` (имя, тип, элемент GUI, границы, значение по умолчанию).

**Экземпляр материала** — строка `MaterialInstance` (материал, имя) и значения его параметров в
`MaterialParameterInstance`. Параметр, которому экземпляр не задал значения, берёт `default_value` из определения.
Так устроен и Material Instance в UE: один шейдер, много наборов значений.

**LOD модели** (`ModelProperties`) ссылается на оба: `material_id` — каким материалом рисовать (очередь отрисовки),
`material_instance_id` — какие значения взять. NULL в `material_instance_id` — значения по умолчанию материала
`material_id`. Экземпляр должен принадлежать тому же материалу; экземпляры 5, 6, 9–12 остались от старой схемы, где эта
колонка означала id материала, и у части старых моделей не совпадают с ним.

## Материал PBR

Модель metallic/roughness описывает поверхность тремя величинами:

- **базовый цвет** — у диэлектрика (дерево, камень, пластик) цвет рассеянного света, у металла — цвет отражения;
- **металличность** — 0 для диэлектрика, 1 для металла; промежуточные значения — для переходов (ржавчина, грязь на
  металле). Диэлектрик отражает около 4 % света (F0 = 0,04) и рассеивает остальное своим цветом, металл только
  отражает, и отражение окрашено базовым цветом;
- **шероховатость** — 0 зеркало, 1 полностью матовая поверхность; от неё зависит, насколько размыт блик.

| Параметр | Тип | По умолчанию | Что это |
|---|---|---|---|
| `BaseColor` | текстура | — | базовый цвет (sRGB), альфа — прозрачность |
| `BaseColorFactor` | цвет RGBA | 1, 1, 1, 1 | множитель базового цвета |
| `MetallicRoughness` | текстура | — | упаковка glTF: канал G — шероховатость, B — металличность (линейная) |
| `Metallic` | 0…1 | 0 | множитель металличности |
| `Roughness` | 0…1 | 0,5 | множитель шероховатости (меньше 0,045 не бывает) |
| `Normal` | текстура | — | карта нормалей в касательном пространстве (линейная, три канала) |
| `NormalScale` | 0…2 | 1 | сила рельефа карты нормалей |
| `NormalGreenUp` | да / нет | нет | зелёный канал смотрит вверх по картинке — соглашение OpenGL и glTF (как Flip Green Channel в UE) |
| `Occlusion` | текстура | — | канал R — затенение окружающего света (ambient occlusion, линейная) |
| `OcclusionStrength` | 0…1 | 1 | сила затенения |
| `Emissive` | текстура | — | свечение (sRGB) |
| `EmissiveFactor` | цвет RGB | 0, 0, 0 | множитель свечения; при нуле свечения нет |

Значение текстуры — id из таблицы `Textures`. 0 означает «текстура не задана»: вместо неё берётся белая текстура 1×1
(для `Normal` — плоская нормаль), и работает один множитель. Id, файл которого не загрузился, даёт пурпурно-чёрную
шахматку — так видно, что текстуры не хватает.

Карта нормалей по умолчанию ждёт соглашение DirectX: зелёный канал — вниз по картинке, туда же, куда растёт v развёртки
(бинормаль меша). Карты из Blender, Substance в режиме OpenGL и glTF — с `NormalGreenUp = true`.

`PBRInstance` (материал 9) — тот же шейдер для расстановки: вершинный шейдер читает положение, размер и поворот
инстанса (см. [scatter.md](scatter.md)), альфа базового цвета режется порогом 0,9 (define `ALPHA_TO_COVERAGE`).
У двусторонних наборов задняя грань освещается как передняя.

## Освещение

- **Прямой свет** — источники `Scene\Lights.ini` (`[General] Count`, секции `[Light0]`…: `Type=Dir|Point`, `Color`,
  `Position`; у направленного источника `Position` — направление на свет). BRDF — Cook-Torrance с распределением GGX,
  геометрическим членом Смита и Френелем Шлика (`Shaders/PBR_common.hlsl`), шероховатость переводится в α = r².
- **Окружающий свет** — полусфера: секция `[Ambient]`, `SkyColor` для направлений вверх, `GroundColor` вниз (без секции —
  0,15, 0,15, 0,156 и 0,075, 0,069, 0,063). Рассеянная часть берёт цвет по нормали, отражённая — по вектору отражения
  с долей `EnvBRDFApprox` (аналитическая замена таблицы BRDF, Karis 2014); обе умножаются на затенение `Occlusion`.
  Тот же окружающий свет получает террейн.
- **Экспозиция и тонмаппинг** — шейдер пишет линейный HDR-цвет без ограничения сверху, экспозицию и тонмаппинг (AgX или
  ACES) применяет постобработка кадра, см. [postprocess.md](postprocess.md). Яркости в `Lights.ini` подобраны под
  экспозицию 0 EV: солнце `Color=3`, небо 0,15 — соотношение солнца и неба как у дневного света.

## Цветовые пространства

Колонка `Textures.sRGB` говорит, что лежит в текстуре: 1 — цвет, закодированный в sRGB (базовый цвет, свечение,
обычные фотографии и рисунки), 0 — данные (карты нормалей, `MetallicRoughness`, затенение, маски, карты высот, шум).
Движок меняет только толкование формата, байты остаются прежними; метаданные файла (чанк sRGB в PNG) не учитываются.
Неверный флаг даёт блёклый цвет (цвет прочитан как данные) или искажённые нормали и шероховатость (данные прочитаны как
цвет). Мипы (`generate_mipmap = 1`) строятся при загрузке после выбора пространства; у DDS со сжатием BC мипы должны
быть в файле.

## Как добавить

Экземпляр PBR для модели — базовый цвет из текстуры, шероховатость 0,8:

```sql
INSERT INTO Textures (name, file, generate_mipmap, sRGB) VALUES ('crate_color', 'models\crate_color.png', 1, 1);
INSERT INTO MaterialInstance (id_material, name) VALUES (12, 'Crate');

-- значения: пары «параметр материала 12 — строка значения»
INSERT INTO MaterialParameterInstance (id_instance, id_material_def, value)
SELECT (SELECT id_instance FROM MaterialInstance WHERE name = 'Crate'), id_parameter_def,
       CASE param_name WHEN 'BaseColor' THEN (SELECT id FROM Textures WHERE name = 'crate_color')
                       WHEN 'Roughness' THEN '0.8' END
FROM MaterialParameterDef WHERE id_material = 12 AND param_name IN ('BaseColor', 'Roughness');

UPDATE ModelProperties SET material_id = 12,
       material_instance_id = (SELECT id_instance FROM MaterialInstance WHERE name = 'Crate')
WHERE model_id = <id модели>;
```

Значения хранятся строками: число `0.8`, вектор `1.0,0.5,0.2,1.0`, логическое `true` / `false`, текстура — её id.
Для модели расстановки то же самое с материалом 9 (`PBRInstance`).

Новый параметр материала — строка `MaterialParameterDef`: `value_type` (0 BOOL, 1 FLOAT, 2 VECTOR2, 3 VECTOR3,
4 VECTOR4, 5 INT, 6 UINT — id текстуры), `control_type` для GUI (1 ползунок, 2 выбор цвета, 3 перетаскивание,
4 текстура), `low` / `high` — границы ползунка, `default_value` — строка значения по умолчанию.

## Управление

Клавиша I включает курсор, дальше в окне свойств у модели раскрываются параметры её LOD: ползунки `Metallic`,
`Roughness`, выбор цвета `BaseColorFactor` и остальные меняют вид сразу. В базу изменения не сохраняются.
Таблица шаров на уровне `Test` (`PBR_Dielectric_R01…R09`, `PBR_Metal_R01…R09` — шероховатость 0,1…0,9) — эталон
для проверки освещения после правок шейдеров.

## Ограничения

- Экспозиция ручная (без автоэкспозиции), единицы света условные, а не физические (люксы, EV100).
- Нет освещения окружением по-настоящему (IBL): металл отражает только двухцветную полусферу и выглядит тусклее,
  чем в Blender или UE.
- Источники света без теней; одна развёртка (TEXCOORD0) на все текстуры, без `KHR_texture_transform`.
- Прозрачность — только порог альфы у `PBRInstance`; полупрозрачный PBR (стекло) не поддерживается.
- Нет расширений материала glTF: clear coat, sheen, transmission, specular.

## Если что-то не так

1. **Шахматка** — не загрузился файл текстуры (в `log.txt` есть строка о нём) или id указывает на несуществующую строку.
2. **Модель белая** — экземпляр не нашёлся или относится к другому материалу: смотрите в `log.txt` строки
   «Material instance … is not found» и «Wrong value of parameter».
3. **Цвет блёклый или слишком тёмный** — неверный `Textures.sRGB` у текстуры цвета.
4. **Выпуклости выглядят вдавленными, свет на рельефе с другой стороны** — переключите `NormalGreenUp`.
5. **Нет блика** — шероховатость близка к 1 или источник светит сзади; **всё блестит** — шероховатость близка к 0.
6. **Металл тёмный** — так и должно быть без IBL: металл не рассеивает свет, а отражать ему пока почти нечего.

## Откуда подход

- Khronos, спецификация glTF 2.0, материал metallic-roughness — набор параметров, упаковка каналов, соглашение
  о зелёном канале.
- B. Karis, «Real Shading in Unreal Engine 4» (SIGGRAPH 2013) — GGX, Смит, Шлик, α = roughness², металличность вместо
  отдельного specular.
- B. Karis, «Physically Based Shading on Mobile» (2014) — `EnvBRDFApprox`.
- B. Burley, «Physically-Based Shading at Disney» (2012) — metallic/roughness как параметры для художника.
- Окружающий свет полусферой — как Ambient Source: Gradient в Unity и Hemisphere Light в three.js.
