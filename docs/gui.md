# Редактор: окна и управление

Интерфейс движка поверх сцены устроен как редактор UE:
- главное меню сверху;
- слева Outliner (что есть на уровне), справа Details (свойства выбранного), снизу Output (консоль и лог);
- в центре — сцена с оверлеем FPS и времени кадра.

Панели прилипают к краям экрана и складываются вкладками (ImGui ветки docking). Перетащить панель за заголовок — к
другому краю или вкладкой к соседней; «Window → Reset layout» — раскладка по умолчанию. Раскладка запоминается в
`imgui_editor.ini` в корне проекта (не в git). Код — `src/Engine/Graphics/GUI/`.

## Управление

| Клавиша | Что |
|---|---|
| правая кнопка мыши + мышь | смотреть камерой — над сценой, не над панелями; курсор прячется и стоит на месте, затем виден там же. Поворот мышью (и в полёте, ходьбе, виде игры) — только у активного окна: после Alt+Tab курсор свободен |
| W A S D, пробел / C | двигать камеру |
| I | режим полёта: камера смотрит мышью всегда, без правой кнопки |
| F | полёт ↔ ходьба по рельефу (см. «Ходьба»); в ходьбе W A S D — шаг, Shift — бег, пробел — прыжок |
| G | вид игры: редактор скрыт, камера смотрит мышью |
| Q | каркас |
| 1 | рельеф вкл / выкл |
| 3 / 4 | расстановка: расчёт / отрисовка |
| P | снимок с окнами редактора (`screenshotN.jpg`) |
| левая кнопка по сцене | выбрать экземпляр модели (клик в пустоту — снять выбор) |
| 5 / 6 / 7 | гизмо выбранного: перемещение / поворот / масштаб |
| Delete | убрать выбранный во вьюпорте экземпляр модели или источник света (Ctrl+Z вернёт) |
| Ctrl+S | сохранить уровень (правки окон) |
| Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) | отменить / повторить правку |
| `` ` `` | консоль |
| перетаскивание по числу вбок | изменить значение (как в Blender: от движения мыши, без прыжка к точке клика) |
| Shift / Ctrl при перетаскивании | вдесятеро точнее / шагами |
| клик по числу без движения | ввести число (Enter — принять, Esc — отменить; можно и за границы поля) |
| стрелки ‹ › по краям числа | шаг вниз / вверх |
| Esc | выход |

Пока набирается текст (поиск, консоль), горячие клавиши и WASD не срабатывают. Список — «Help → Hotkeys».
С `-nomouse` камера мышь не читает совсем, как раньше.

## Меню

- **File** — действия: «Save level» (Ctrl+S), «Exit». Действия выполняет и консольная команда
  `action "<имя>"` (удалённое управление, [remote.md](remote.md)). Подменю **Preset: <имя>** — пресеты окружения
  уровня и «Save preset as…» (см. «Пресеты окружения»).
- **Edit** — «Undo …» / «Redo …» с именем правки (Ctrl+Z / Ctrl+Y), см. «Отмена правок».
- **View** — переключатели с отметкой состояния: каркас, рельеф, расстановка, режим полёта, вид игры; оверлей кадра.
  Это те же горячие клавиши — меню нажимает их (`KeyEventNotifier::press`). Подменю **Debug views** — отладочные виды
  одним списком: раскраска LOD террейна, вода на земле, поле ветра, каскады теней, затенение окружением, след лучей
  солнца (флажки окон объектов,
  `Editor::Toggle::debugView`).
- **Window** — панели вкл / выкл, «Reset layout».
- **Help** — горячие клавиши.

Справа в меню — «Level changed — Ctrl+S to save», пока в окнах, сохраняемых с уровнем, есть правки после загрузки или
сохранения.

## Панели

- **Outliner** — окна свойств по разделам:
  - **Environment** — свет и время суток, небо или панорама, облака, туман, постобработка, ветер;
  - **Scene** — объекты сцены: террейн, модели, вода, наборы расстановки, частицы, мир симуляции («World», [simulation.md](simulation.md));
  - **Rendering** — рендерер и тени.

  Флажок слева — видимость объекта сцены (`SceneObject::setVisible`). Звёздочка — есть изменения после загрузки или
  сохранения. Поиск по имени.
- **Details** — свойства выбранного таблицей «имя | значение | reset»:
  - подконтейнеры (подокно солнца, слой расстановки) — сворачиваемые заголовки;
  - изменённое после загрузки или сохранения подсвечено; «reset» возвращает свойство, «Reset all» — всё окно;
  - кнопки окна — под его свойствами (`PropertyContainer::addButton`, как функции CallInEditor в UE): действие над
    объектом окна — у «Lights» «Add directional / point / spot light», у подокна источника «Delete», у «Model
    instances» подокно «Add» с кнопкой на модель, у подокна экземпляра «Delete». Нажатие
    выполняется после отрисовки панелей (`PropertyWidgets::takePressedButton` → `GUI::press`): действие может убрать
    подокно, которое только что рисовалось; действие с отменой — правка истории;
  - поиск по свойствам (под поиском заголовки раскрыты);
  - единица свойства (`Property::setUnit`) — в скобках после имени, у любого контрола: «Far border (m)», «Stream gravel
    speed (m/s)» (у пар «от, до» и векторов в значении её не было, у чисел значение теперь без неё — Dimok, 2026-10-14);
    единица — только так, а не в имени: прежние «Time of day (h)», «Intensity (lx)», «Speed (m/s)» стали «Time of day»,
    «Intensity», «Speed» с единицей (2026-10-14, обход всех окон — `list` печатает единицу после значения); в имени —
    только у пары с разными единицами («Compensation curve key 1 (EV100, EV)»), такое имя окно не трогает. Номера
    режимов — список (`COMBO`), не подсказка в имени: «Metering mode», «Tonemapper». Не влезает в колонку — имя
    сокращается многоточием, единица остаётся: «Displacement dis... (m)». Имя для команд `set` — без единицы, без «/»
    (`PropertyContainer::insert` проверяет `assert`);
  - наведение на имя — полное имя с единицей и подсказка;
  - формат числа — по величине (0,0003 не превращается в 0,000), величины в несколько порядков — логарифмическая шкала
    (`Property::setLogarithmic`, `settingLogarithmic`): своя, а не флаг ImGui (у него «ноль» шкалы — точность формата,
    и при нижней границе 0 малые значения были недостижимы, а пиксель перескакивал на сотые). На ширину поля — четыре
    порядка до верхней границы (у плотности тумана до 0,02 — от 0,000002; пиксель — ×1,05, с Shift — ×1,005), левее
    начала шкалы — нижняя граница (0), заливка — доля на той же шкале; стрелки — единица старшего разряда (0,00006 →
    0,00007), Ctrl — значение до старшего разряда;
  - числа — поля как в Blender (`PropertyWidgets::numberField`), ползунков нет: перетаскивание вбок меняет значение от
    движения мыши, клик без движения — ввод числа (`io.ConfigDragClickToInputText`), стрелки по краям при наведении —
    шаг, Shift — вдесятеро точнее, Ctrl — значение кратно шагу (перетаскивание копится в «сыром» значении, на поле —
    оно, округлённое до шага: округлять само значение нельзя — мелкие движения возвращались бы назад). Шаг — у свойства
    (`Property::setStep`, как step у свойств Blender: у времени суток — 0,25 ч, у поля зрения — 1°), без него — степень
    десяти около трёх пикселей перетаскивания (у доли 0…1 на поле в 200 пикселей — 0,01, у метров 0…200 — 1). У свойства с границами (`SLIDER`)
    — заливка доли диапазона, как у фактор-слайдеров Blender, и весь диапазон на ширину поля; у `DRAG` — шаг
    `Property::setDragSpeed`, иначе по величине значения. Векторы — по полям, клик — ввод, Shift — точнее. Тем же
    полем — «Falloff» кривых русел и размер миниатюр Texture Library.
- **Output** — вкладки:
  - **Console** — те же команды, что у удалённого управления: строка выполняется в начале следующего кадра, ответ — в
    окне. ↑ / ↓ — история, Tab — дополнение имени команды и пути свойства для `get` / `set` / `list` (путь с
    пробелами — в кавычках);
  - **Log** — последние 2000 строк `log.txt` с поиском, ошибки красным, предупреждения жёлтым, флажок «только ошибки
    и предупреждения».
- **Stats** — таблица времени CPU и GPU проходов и объектов (сортировка по колонке) и прочие счётчики кадра (память,
  кольцо констант, барьеры). Оверлей поверх сцены — FPS, кадр CPU и GPU и графики за 300 кадров.
- **Camera** — положение, направление, строка `x,y,z,pitch,yaw` для команды `camera` и параметра `-Camera` с кнопкой
  копирования, скорость камеры, поле зрения, ближняя и дальняя плоскости (начальные — `settings.ini`, из окна не
  сохраняются).
- **Texture Library** (Window) — текстуры хранилища миниатюрами с поиском, наведение — крупно с id и размером.

## Ходьба

F (или View → «Walk on terrain») переключает камеру с полёта на ходьбу от первого лица, как Character Movement в UE:
персонаж мира столкновений (`WalkMode`, `Scene/Camera/WalkMode.h`; капсула Jolt — [physics.md](physics.md)):

- глаза на «Eye height» (1,7 м) над ногами, капсула — на 0,1 м выше глаз, радиус «Radius» (0,3 м); земля — та же, что
  рисует LOD 0 (`TerrainHeightSource::surfaceHeight`; у русел — детальные плитки 0,25 м);
- модели уровня (по их простой коллизии, `Models.collision`) и сущности мира преграждают путь — у препятствия
  скользишь вдоль него;
- включение в воздухе — падение до земли с гравитацией, под землёй — сразу на поверхность; выключение — полёт с того же
  места;
- шаг 1,4 м/с, с Shift — бег 5 м/с, разгон и торможение плавные, в воздухе управления почти нет; пробел — прыжок
  (4,5 м/с — ~1 м вверх);
- склон круче «Max slope» (40°) вверх не пускает, стоя на таком — съезжаешь вниз; ступенька ниже «Step height»
  (0,4 м) — шаг вверх, выше — стена; уступ мельче — сходишь, глубже — падение; подъём взгляда на ступеньке сглажен;
- вода глубже «Max wade depth» (1 м) не пускает — у берега идёшь вдоль него, мельче — вброд (0 — вода не мешает);
- камера в ходьбе смотрит мышью всегда, как в режиме полёта (I); команда `camera` камеру идущего не переносит —
  выключите ходьбу (F), перенесите, включите;
- земля у ног — самой мелкой сеткой рельефа: LOD террейна при ходьбе считается от отрезка «глаза — ноги»
  (`WalkMode::eyeAboveFeet` → `RenderView::lodEyeHeight`), радиус — «Finest mesh radius» окна террейна
  ([terrain.md](terrain.md), «Детальная земля у русел»).

Настройки — окно «Walk» (раздел Rendering, не сохраняются). Трава у ног расступается — окно «Foliage interaction»
([wind.md](wind.md), «Трава расступается»). Ограничения: лес и камни расстановки пока проходятся насквозь — их тела
появятся следующим шагом (`TODO.md`, «Столкновения»).

## Вьюпорт

Сцена под панелями — вьюпорт, как в UE (`Viewport`, `GUI/Viewport.h`):

- **Выбор.** Клик по сцене (нажатие не над панелью и отпускание почти на месте) — луч из камеры через курсор к повёрнутым
  границам LOD 0 экземпляров моделей (`ModelInstances::pick`), выбирается ближайший. Выбранный обведён рамкой с именем,
  в Outliner выбрано окно «Model instances», в Details его подокно раскрыто и прокручено к нему (`GUI::focusProperties`).
  Выбирается по границам, а не по треугольникам: крупная плоскость перехватывает клик по тому, что за ней. Выбор хранится
  ключом экземпляра (`ModelInstances::key`), как у источников: номера после добавления и удаления сдвигаются.
- **Добавление и удаление экземпляров** — окно «Model instances»: подокно «Add» (первое) — кнопка на модель палитры
  (`ModelInstances::palette`: модели экземпляров уровня при загрузке; у моделей расстановки материал для пула —
  экземпляром уровня их не нарисовать, новые модели — `Tools/import_gltf.py`). Новый экземпляр (`QuickAdd::addModelInstance`, `GUI/QuickAdd.h`)
  встаёт туда же, куда новый источник света (центр взгляда на земле ближе 200 м, иначе в 10 м перед камерой —
  `QuickAdd::placementInFront`), низом границ LOD 0 на землю, как End; без поворота, масштаб 1; выбран во вьюпорте,
  до «Save level» отмечен «*» и назван «new ключ: модель». «Delete» в подокне экземпляра или Delete во вьюпорте — убрать
  выбранный; Ctrl+Z возвращает его на прежнее место с теми же свойствами (`ModelInstances::addInstance` / `removeInstance` /
  `restoreInstance`).
- **Гизмо** (ImGuizmo) у выбранного: перемещение, поворот, масштаб — кнопки над сценой или 5 / 6 / 7, «Local axes» — оси
  экземпляра (у масштаба — всегда свои). Перетаскивание пишет матрицу в свойства окна (`ModelInstances::setInstanceMatrix`:
  положение, углы, масштаб), поэтому отметка изменённого, «reset» и «Save level» работают как при правке в Details.
  Над панелями гизмо мышь не берёт. ImGuizmo понимает обратную глубину: луч берётся от ближайшей к камере точки.
- **На землю** — «Snap to terrain» (File, End, как в UE; `ModelInstances::snapToTerrain`): выбранный экземпляр
  сдвигается по высоте так, что низ его границ LOD 0 ложится на самую высокую точку земли под ними (сетка 5 × 5 точек
  `TerrainHeightSource::surfaceHeight`). Правка — через свойства окна, как у гизмо. Все экземпляры уровня сдвигаются так
  же сами, когда сменился рельеф после эрозии ([terrain.md](terrain.md), «Эрозия»).
- **Источники света** — значками поверх сцены (`Viewport::drawLights`): точечный — диск с кольцом на месте, прожектор —
  то же с линией направления на 2 м, направленный — в небе, откуда идёт свет (на 1 км от камеры против направления):
  солнце — диск с лучами, луна (`atmosphere_sun_light_index` 1) — серп; цвет — цвет источника, выключенный — серый.
  Клик по значку (ближе 14 пикселей; раньше экземпляров моделей) выбирает источник: он обведён, подписан, Details
  раскрывает его подокно в окне «Lights». Правка — через свойства подокна, поэтому отметка изменённого, «reset», «Save
  level» и отмена (Ctrl+Z) работают как в Details:
  - **точечный** — гизмо перемещения (`Position`);
  - **прожектор** — перемещение и поворот (кнопки над сценой, 5 / 6): ось +Z гизмо — направление света, поворот пишется
    в `Pitch` / `Yaw` (`DMLightDriver::rotationFromDirection`);
  - **направленный** — значок тянут по небу: свет идёт из-под курсора (`Pitch` / `Yaw`). Солнце и луну при
    `SunPosition` ведёт время суток — их тянут вдоль их дуги: время, при котором светило ближе всего к курсору (сутки
    по 5 минут, затем по 10 секунд вокруг лучшего), пишется в «Time of day» подокна «Sun position».

  **Добавление и удаление** — кнопки окна «Lights» (`QuickAdd::addLight`, `DMLightDriver::addLight` / `removeLight`):
  «Add … light» ставит новый источник туда, где центр взгляда упирается в землю (ближе 200 м, иначе в 10 м перед
  камерой; точечный — не ниже 1,5 м над землёй, прожектор — 3 м и светит вниз, направленный — под 45° вниз по взгляду;
  модели место не задают — только рельеф), новый выбран во вьюпорте и раскрыт в Details, до «Save level» отмечен «*»;
  «Delete» в подокне источника или клавиша Delete во вьюпорте — убрать выбранный. Выбор во вьюпорте хранится ключом
  источника (`DMLightDriver::key`): номера в списке и в именах подокон («2: Point light (point)») после добавления и
  удаления сдвигаются. Настройки нового и что бывает с солнцем времени суток — [lighting.md](lighting.md), «Правка в GUI».
- **Эмиттеры частиц** с местом — в точке и в шаре (`spawn` = `point` / `sphere`; поле вокруг камеры и брызги на
  воде места не имеют) — значком на месте (`Viewport::drawEmitters`): точка и шесть точек вокруг цвета частиц,
  выключенный — серый. Клик выбирает ближайший значок — источника света или эмиттера (у костра они рядом); Details
  раскрывает подокно эмиттера в окне «Particles», у шара видна его граница — три окружности по плоскостям мира. Гизмо
  перемещения пишет свойство «Position» (место экземпляра `LevelParticleEmitters`), поэтому отметка изменённого,
  «reset», «Save level» и Ctrl+Z — как у прочих свойств.
- **Кривые русел** — View → «Stream curves»: оси ручьёв ближе 250 м — линии с точками; клик по точке выбирает её (клик
  мимо точек — экземпляр модели), Details раскрывает подокно кривой в окне «Water simulation» → «Streams»; гизмо двигает
  точку по X и Z (высота — земля под ней), Insert — новая точка после выбранной, Delete — удалить; «Falloff» над сценой —
  мягкое выделение: соседние точки по длине кривой сдвигаются вместе с выбранной. Отпустили гизмо — русла, вода и лес
  перестраиваются без перезагрузки уровня, «Save level» пишет точки ([water.md](water.md), «Кривые русел»).
- **Кисть слоёв и масок** — View → «Terrain paint»: круг кисти на рельефе под курсором (внутренний — где кончается мягкий
  край; цвет — режим: белый — значение, зелёный — шаг, красный — убавить, серый — стереть) и подпись с целью; ЛКМ — мазок,
  Shift — убавить в режиме «Step», Ctrl — стереть мазок (к правилам). Настройки — подокно «Paint» окна террейна: «Target»
  (слой земли или мокрость — сетка 0,25 м, маска — 1 м), «Mode» («Value» — итог к значению, «Step» — ± значение за мазок), «Value», «Radius», «Falloff», «Show target» — цель
  кисти поверх земли, пока режим включён: оранжевым по значению (вес слоя, мокрость, маска), тёмные изолинии через 0,25;
  с уровнем не сохраняются (окно `setTransient`). Мазок — одна правка истории (Ctrl+Z / Ctrl+Y: плитки цели до и после),
  земля и кольцевая трава меняются вживую, лес раскладывается заново, когда ЛКМ отпустили; «Save level» пишет мазки
  ([terrain.md](terrain.md), «Ручная правка слоёв и масок»). В этом режиме клик по сцене ничего не выбирает.
- **Удалённое управление:** `pick x y` — тот же выбор лучом через точку окна (снимки выбора сценарием; в режиме кривых —
  точка кривой, затем значок источника света или эмиттера; ответ — имя выбранного), `toggle "<имя>"` — переключатель View, `stream move x,z | insert | delete | falloff м` — правка точки, `brush x y [x y …] [shift] [ctrl]` — мазок кисти через
  точки окна, как мышью (с отменой).

Рамка, значки источников и гизмо рисуются в фоновый список ImGui — под панелями, поверх сцены (значок виден и сквозь
геометрию).

## Сохранение уровня

«Save level» (File, Ctrl+S, `action "Save level"`) пишет в `base.db3` правки окон, сохраняемых с уровнем, — у них в
Details строка «Saved with the level», у остальных — «Not saved: changes last until exit»:

| Окно | Куда |
|---|---|
| Lights, Sky atmosphere / HDRI backdrop, Volumetric cloud, Height fog, Post process, Wind | строки окружения уровня (`LibraryLoader::saveLevelEnvironment`); новые источники света — новые строки `LevelLights` (id пишется в источник), убранные — удаляются |
| Model instances | строки `LevelModels`: положение, поворот (кватернион из углов окна), масштаб ([models.md](models.md)); новые экземпляры — новые строки (id пишется в экземпляр, подокно — «id: модель»), убранные — удаляются; пересадка на рельеф после новой эрозии закрепляется — `eroded\previous.dds` удаляется |
| CDLOD terrain | строка `Terrain` (множитель высоты, triplanar, смешение по высоте, второй масштаб), `tiling` и `albedo_tint` строк `TerrainLayers` («Layer tiling», «Layer tint») и строка `TerrainErosion` (подокно «Erosion»; новая эрозия — при следующей загрузке) |
| Наборы расстановки | строки `ScatterLayers` (шаг, кольцо, исчезание, размер, разброс, поворот, выравнивание, тень, дальность и настройки импостера) и `ScatterLayerModels` (вес и тень варианта, кольца LOD — `lod_distances`) |
| Water simulation | строка `WaterSimulation` уровня (источники, дождь, Маннинг, поверхность, течение озёр — подокно «Flow»), `WaterChannels` (подокно «Channels») и строки `Streams` (подокно «Streams»: включение и множители кривых русел; изменённая кривая помечается правленной — [water.md](water.md), «Кривые русел») |
| Particles | строки `ParticleEmitters` (всё, кроме способа рождения, формы, маски и ёмкости) и место экземпляров `LevelParticleEmitters` (у эмиттера в точке и в шаре) |

Объекты сцены — `LibraryLoader::saveLevelScene` (`LibraryLoaderScene.cpp`), окружение и объекты — две транзакции подряд
(`Scene::saveLevel`). Состав уровня (какие слои, модели, эмиттеры) не меняется, только колонки строк, — кроме источников
света и экземпляров моделей: их добавляют и убирают кнопками окон «Lights» и «Model instances». Не сохраняются:
окна Renderer, Shadows, Camera, Models (параметры материалов, «Shadow LOD scale» и «Shadow min LOD» моделей), «Enabled» у ветра и
эмиттеров — выключатели кадра: `-nowind` снимает «Enabled» у ветра, а сила остаётся, поэтому сохранение с `-nowind` её
не затирает.

**Пишутся только правки**, как несохранённые изменения в редакторе UE. `Scene` держит снимок окон уровня — `LevelSaveData`
(`Scene/Level/LevelSaveData.h`): он снимается после загрузки, когда окна зарегистрированы (`Scene::markLevelSaved`, там же
`Property::markSaved`), и после каждого сохранения. «Save level» собирает окна заново (`Scene::levelSaveData`) и пишет в
строку только колонки, значение которых отличается от снимка (`RowUpdate`, `ObjectLibrary/SettingsDatabase.h`). Сравнение —
в том виде, как значение ляжет в базу (число — `%g`, вектор — текст `x,y,z`), поэтому шум пересчёта углов окна в вектор
правкой не считается. Остальное в строке не трогается: NULL (значение по умолчанию) остаётся NULL, значение, записанное
сценарием `Tools/`, — тоже. Строка уровня, которой нет (постобработка, ветер, туман, атмосфера вместо незагруженной
панорамы), создаётся, только если в её окне что-то поменяли. Производное не пишется: направление солнца и луны считает
`SunPosition` по времени суток, освещённость луны — по фазе (`DMLightDriver::directionFromTime` / `moonFromTime`), — у
строки, которая уже есть в базе, эти колонки остаются как были. Экземпляры моделей сравниваются с тем, что загружено из
базы: пересадка на новую землю после эрозии — правка, «Save level» её закрепляет. Мазки кисти и точки кривых русел
переписываются, только если их правили. «Save level» без правок на `Test` и `TestHDRI` не меняет в базе ничего
(2026-10-15; было 33 и 31 колонка — NULL → число, у `TestHDRI` без файла панорамы ещё новая строка `SkyAtmosphere`).

## Пресеты окружения

Пресет — именованный набор строк окружения уровня, как снимок в Level Snapshots UE: время суток (`SunPosition`), небо
(`SkyAtmosphere`), постобработка с цветокоррекцией и экспозицией (`PostProcessSettings`), ветер (`Wind`), туман
(`ExponentialHeightFog`), облака (`VolumetricCloud`). Рельеф, вода, расстановка, модели, свет и панорама HDRI — общие для
всех пресетов: это содержимое уровня. Зачем: окружение подбирают на глаз, а проверки рендера (`Tools/check_frames.py`)
сравнивают кадры с эталоном — у них свой заблокированный пресет `Reference`, и подбор в редакторе эталон не сдвигает.

- **Данные** — таблица `LevelPresets`: уровень, имя, id строк окружения (колонки — как у `Levels`: `sun_position`,
  `atmosphere`, `post_process`, `wind`, `height_fog`, `volumetric_cloud`; NULL — строка самого уровня, общая с ним) и
  `locked`. Строки самого уровня (`Levels`) — пресет «Level», рабочий по умолчанию. Загрузчик —
  `ObjectLibrary/LibraryLoaderPresets.cpp`: строки пресета подставляются в `LevelDescription::*Id`, их читают окна и в
  них пишет «Save level» (`LevelDescription::levelRows` — строки уровня, `preset`, `presetLocked`, `presets`).
- **Выбор при запуске** — `[Level] Preset=` в `settings.ini` или параметр `-preset <имя>` (`--preset` у `engine.py start`,
  `-Preset` у `run.ps1`); нет такого — строки уровня и строка в логе. `check_frames.py` запускает с `--preset Reference`.
- **Выбор на лету** — File → Preset: <имя> (галочка у активного) или команда `preset <имя>` (`preset level` — строки
  уровня, `preset` — список). Настройки пресета пишутся в окна (`writeSettingProperties` — обратное
  `readSettingProperties`, у объектов — `apply`: `SunPosition`, `SkyAtmosphere`, `VolumetricCloud`, `Wind`, `PostProcess`,
  `VolumetricFog`), окна становятся «сохранёнными», несохранённые правки окружения отбрасываются, история правок
  очищается (отмена вернула бы значения прежнего пресета в новый). Ключей кривой компенсации экспозиции в окне — сколько
  было при загрузке.
- **«Save preset as…»** (File → Preset, команда `preset save <имя>`) — окружение в окнах становится новым пресетом:
  копии строк активного пресета (имя строк — «уровень пресет») плюс правки окон; новый пресет становится активным, прежний
  остаётся как был сохранён. Имя — новое, без «/».
- **Заблокированный пресет** (`locked` = 1, `Reference` у `Test`): «Save level» пишет всё, кроме окружения (свет, рельеф,
  расстановка — как обычно), и предупреждает; правки окружения остаются несохранёнными — их переносит «Save preset as».
  Блокировку снимают и ставят в базе.
- **Что входит в пресет — видно цветом** (`PropertyWidgets::presetColor`, бирюзовый): имя окна в Outliner, строки свойств
  и заголовки подокон в Details (`PropertyContainer::setPresetPart`, наследуется подокнами; у «Lights» в пресете только
  подокно «Sun position»), в шапке Details — «Preset <имя>: other presets keep their values» и у заблокированного —
  «Locked: Save level skips it». Такие контролы можно двигать: эталон проверок не меняется.

## Как дать объекту свойства

Объект сцены отдаёт `properties()` — `PropertyContainer` (`src/Common/Properties`); `Engine::initialize` регистрирует
его в Outliner (`GUI::addPropertyWatching( контейнер, раздел, объект, сохраняется )`). Раздел Environment у объекта —
`SceneObject::environment()`, сохранение с уровнем — `SceneObject::savedWithLevel()` (у окружения — всегда): объект
отдаёт настройки по своим свойствам (`settings()`, `layerRecords()`), а `Scene::saveLevel` передаёт их загрузчику —
объекты о базе не знают. Контролы панель строит сама по типу значения и `GUIControlType` — один шаблон
(`PropertyWidgets::controlCell`) на все окна: у числа — поле как в Blender (`SLIDER` — с заливкой доли и границами,
`DRAG` — без них), `LABEL` — только чтение, у `XMFLOAT2` с `RANGE` — полоса «начало — конец» парой полей
`DragFloatRange2`: конец не уходит за начало, у `int32` с `COMBO` — выпадающий список имён (`Property::setItems`, значение —
номер имени; `set` — тоже номер). Подокно, которое не данные уровня (кисть), — `PropertyContainer::setTransient`: его правки
не делают уровень изменённым; отдельное такое свойство (флажок «Visible» слоя расстановки) — `Property::setTransient`. Необязательно:

```cpp
properties.insert( "Density", density )->setLow( 0.0f );            // как раньше
property->setUnit( "1/m" )->setLogarithmic()->setFormat( "%.5f" )
        ->setTooltip( "Extinction coefficient; visibility ~3 / density" );
property->setStep( 0.25f );                                         // шаг стрелок и Ctrl; без него — подбор
```

**Настройки уровня — описанием полей** (`SettingsSchema`, как UPROPERTY в UE): у строки базы, которую окно правит и
«Save level» пишет, параметр описывается один раз — колонка базы, имя свойства, член структуры настроек, границы,
единицы, подсказка, флаги, часть окна и выбор из значений. По описанию строятся свойства окна (`addSettingProperties`,
`Properties/SettingsProperties.h`) и структура из них (`readSettingProperties`), читается строка базы (`readSettings`,
`SELECT *`: NULL — значение по умолчанию структуры, нет колонки — тоже, со строкой в лог) и пишется `UPDATE`
(`updateSettings` или `settingsAssignments` + `bindSettings`; `INSERT` — по `settingsColumns`, `ObjectLibrary/SettingsDatabase.h`).
Описания — рядом с данными, в `Scene/Level/LevelSettings.cpp` (тени солнца — `DMLight::shadowSchema`):

```cpp
const SettingsSchema<TerrainSettings>& terrainSchema()
{
	using Settings = TerrainSettings;
	static const SettingsSchema<Settings> schema = {
		{ "height_blend", "Height blend", DM_SETTING( heightBlend ), 0.01f, 1.0f, "", "Depth of the height-based blend between layers" },
		// полоса «от — до» (SettingRange) в двух колонках, в окне — одно двойное поле
		{ "far_blend_start,far_blend_end", "Far blend", DM_SETTING( farBlend ), 0.0f, 1000.0f, "m", "…", settingRangeControl },
		// целое списком с подписями; часть окна "" — основная
		{ "finest_mesh", "Finest mesh", DM_SETTING( finestMesh ), 0.0f, 0.0f, "", "…", 0, "", { 0, 1, 2, 3, 4 },
		  { "25 cm", "12.5 cm", "6.25 cm", "3.1 cm", "1.6 cm" } },
	};
	return schema;
}

addSettingProperties( m_properties, terrainSchema(), settings );	// окно
readSettingProperties( m_properties, terrainSchema(), settings );	// структура из окна
readSettings( query, terrainSchema(), settings, "Terrain 1" );		// строка SELECT *
updateSettings( db, "Terrain", id, terrainSchema(), settings, previous );	// «Save level»: поля, изменённые против снимка
```

Поле:
- **колонка** — одна или колонки компонент через запятую (вектор; полоса `SettingRange` — `slope_from,slope_to`), у вектора
  можно одну текстом «x,y,z»; пусто — поле хранится не в этой строке (месяц и день солнца — в колонке `date`, место
  эмиттера — в строке экземпляра); имя `nullptr` — только в базе (файл панорамы, шаг симуляции воды, маска эмиттера);
- **доступ** — указатель на член (`&TerrainLayerRules::rockSlope` — в таблицах, построенных циклом) или `DM_SETTING( член )`,
  в том числе вложенный (`DM_SETTING( layer.density )` у тумана);
- **флаги**: `settingLogarithmic`, `settingColor`, `settingDrag` (поле без заливки доли — значения на порядки),
  `settingRangeControl` (полоса одним двойным полем), `settingClamp` / `settingClampLow` (пределы при чтении из окна),
  `settingWideHigh` (верхняя граница — не меньше 4 × значения: частота и размер частиц), `settingTransient`;
- **часть окна** `group`: подокно (правила слоёв по группам, «Surface» воды), то, что объект добавляет по условию (место
  эмиттера в точке и в шаре, импостер слоя расстановки), или признак поля (`streamGeneratorGroup` — параметры генератора
  кривых русел: применяются при следующей загрузке и составляют отпечаток генерации); `addSettingProperties` и
  `readSettingProperties` берут все поля или одну часть;
- **выбор** `choices` с подписями `labels`: целое — списком в окне («Finest mesh» террейна, размер кадра импостера).

Целые в окне — `int32` (контрол числа один на оба типа; `uint32` из окна — не меньше 0). Те же описания дают сравнение
(`settingsEqual`, одно поле — `settingFieldEqual`: сменились ли правила слоёв, поле ветра, течение, кривая русла) и обход
значений (`forEachSettingValue` — ключи кэшей масок, поля ветра, течения и отпечаток генерации кривых русел: новое поле
попадает в ключ само). Чтение — без копии структуры (у воды в ней кривые и источники).

Новый параметр — поле структуры, строка описания и колонка в базе; окно, загрузка, «Save level», проверка изменений и ключ
кэша подхватят его сами. Описанием переведены все строки настроек уровня: облака, туман, небо, панорама, постобработка,
солнце (`SunPosition`), ветер и поле ветра, тени солнца, террейн (`Terrain`), эрозия, правила слоёв, вода
(`WaterSimulation`, течение, `WaterChannels`, кривые `Streams`), эмиттеры частиц, наборы и слои расстановки. Объект
дописывает только то, что хранится иначе, чем показывается: направление ветра (в окне — Yaw), дату солнца (месяц и день),
перечисления постобработки (имена) и кривую компенсации (текст), единицу частоты и смысл радиуса эмиттера по способу
рождения; связи полей (дальняя граница слоя не ближе ближней + шаг) и фильтр по ролям земли флажками. Вручную остались
строки, у которых окно — не «поле ↔ колонка» (`TODO.md`, A1b): варианты слоя расстановки (`ScatterLayerModels`: NULL —
«как у слоя», роли флажками, границы LOD по числу LOD модели), сам источник света (`DMLight` — класс, окно по типу
источника), слои материала террейна (`TerrainLayers`: подокна по свойству на все слои) и экземпляры материалов
(параметры — по определениям материала).

**Кнопки окна** — `PropertyContainer::addButton( имя, подсказка, действие )`: действие возвращает
`PropertyContainer::ButtonAction` — функции отмены и повтора (пустые — не отменяется) и имя правки; так источники света
добавляются и убираются (`DMLightDriver`, `QuickAdd::addLight`). Изменился состав окна (подокно добавили или убрали,
объекта окна ещё нет в базе) — владелец ставит `PropertyContainer::setStructureModified`: окно отмечено изменённым, как
после правки свойства, до «Save level» (`markSaved` снимает отметку). Удалённое управление видит кнопки: `list` пишет их
`[имя]`, `press "окно/кнопка"` нажимает.

**Правка идёт** — `Property::editing()`: панель ставит его, пока контрол свойства активен (поле тянут, в него
набирают число или держат стрелку; поле и стрелки — одна группа ImGui), и снимает в конце кадра, если контрол перестали рисовать
(`PropertyWidgets::endFrame`). `PropertyContainer::editing()` — то же с подконтейнерами. Объект, которому правка дорога
(расстановка: новые буферы слоя, раскладка леса на всю карту), применяет её один раз, когда правка закончилась, а
дешёвое — на лету; команда `set` правит сразу (`editing` — false).

**Номер правки** — `Property::revision()`: растёт, когда значение свойства сменилось — `setData` и `setValue` (команда
`set`, история правок, гизмо вьюпорта, код объекта), сброс к сохранённому, правка в окне (контролы ImGui пишут через
`dataPtr`, `controlCell` сверяет значение до и после и зовёт `touchIfChanged`); у нового свойства — тоже новый номер.
Номера — из общего счётчика, поэтому `PropertyContainer::revision()` — наибольший номер свойств со всеми подконтейнерами:
общее подокно (параметры экземпляра материала в окнах моделей и слоёв расстановки) видно в каждом окне, куда вложено.
Объект хранит номер, по которому применил настройки окна, и каждый кадр сравнивает одно число; сменился — сверяет, что
именно правили (дорогое — после конца правки, `editing`). Так проверяют правки слой расстановки (`Scatterer::applyProperties`,
перезапекание импостеров), `Scene::applyEditorChanges` (ветер, правила слоёв, течение, кривые и форма русел) и вода (настройки
кадра — `WaterSimulation::currentSettings`): на `Test` проверка правок стоит ~10 мкс на кадр вместо ~140. Состав окна
(подокно добавили или убрали) номер не меняет — его отмечает `setStructureModified`.

Значения при регистрации — «сохранённые»: от них считается «изменено». После сохранения уровня `GUI::markSaved`
обновляет их у окон, сохраняемых с уровнем. Имя свойства — без «/» (это разделитель пути `set`) и без единицы: её пишет окно по `setUnit` («Name (unit)»). Удалённое управление (`list` / `get` / `set`) видит те же свойства по путям
`окно/подокно/свойство`.

## Экран загрузки

Пока уровень грузится (`Engine::initialize`, в Release ~7 с, в Debug с GPU-based validation ~40 с), окно показывает
панель «Loading level …»: что делается — вложенные шаги через « — » («Scene — Terrain — Rivers and lakes»), полоса
прогресса и секунды с начала. Как Slow Task в UE:
- **шаги** объявляет сам код загрузки — `SlowTask` (`src/Common/Utils/SlowTask.h`, как `FScopedSlowTask`): задача с
  объёмом работы и её части `enterProgressFrame( доля, "текст" )`; вложенная задача делит текущую часть внешней. Доли
  подобраны по времени шагов (Release, уровень `Test`): текстуры моделей, сцена (слои материала террейна, русла и озёра,
  течение озёр), импостеры. Новый долгий этап загрузки — ещё одна часть или задача там, где он выполняется;
- **показ** — обработчик `SlowTask::setHandler`, его ставит `Engine::initialize` до загрузки и снимает в конце:
  `Engine::drawLoadingFrame` откачивает сообщения окна (иначе Windows через 5 с помечает его «не отвечает»;
  закрытие окна — выход сразу после загрузки) и не чаще 30 раз в секунду рисует кадр `GUI::drawLoadingScreen`. Кадр
  выполняет и ждёт записанные команды загрузки (`DMD3D::beginFrame`), после него список открывается снова
  (`DMD3D::resumeLoading`). Поэтому GUI инициализируется сразу после устройства, а части отмечаются только на границах
  этапов: кадр сбрасывает привязки и пайплайн. Без обработчика (перестройка русел в кадре) `SlowTask` ничего не делает;
- **лог** — время верхних частей («Loading: Scene ms: …») и шагов дольше 100 мс («Loading step: … ms: …»): на что
  уходит загрузка.

## Отмена правок

Ctrl+Z / Ctrl+Y (и Ctrl+Shift+Z), меню Edit, команды `undo` / `redo` удалённого управления — как Transactions в UE.
История — `Editor::EditHistory` у `GUI` (`GUI::history`): правка — группа свойств со значениями «до» и «после», до 200
правок. Отмена ставит «до» через систему свойств, повтор — «после»; объекты об отмене не знают — они читают свойства
каждый кадр (у расстановки отмена шага или кольца — тоже одна пересборка слоя). В историю пишут:
- **контрол Details** (поле, стрелка, флажок, цвет, вектор) — одна правка, пока он активен: перетаскивание целиком,
  ввод числа до Enter, клик по стрелке. Граница — по состоянию «правка идёт» (`Property::editing`), а не по событиям
  ImGui: после клика по полю оно на кадр неактивно, пока включается ввод числа, — пустая правка отбрасывается, а ввод
  начинает свою (`PropertyWidgets::controlCell`). Имя правки — «подокно: свойство»;
- **reset** у свойства и **Reset all** у окна — одна правка;
- **гизмо экземпляра модели** — от взятия до отпускания («Move / Rotate / Scale <экземпляр>»; значения «до» сняты до
  кадра, в котором гизмо взяли, — `Viewport::manipulate`), **End** («на землю»);
- **кнопка окна** с отменой — действие целиком (`EditHistory::record`: функции отмены и повтора): «Add … light» и
  «Add» экземпляра — отмена убирает новый, «Delete» (и Delete во вьюпорте) — возвращает убранный на прежнее место с теми
  же свойствами. Убранный источник или экземпляр с подокном живёт до выхода (`DMLightDriver`, `ModelInstances`):
  указатели истории на его свойства остаются верными.

Команда `set` в историю не попадает. Свойства хранятся указателями: контейнеры живут весь сеанс (создаются при загрузке
уровня); объект, который пересоздаёт контейнер во время работы, должен сбросить историю (`EditHistory::clear`). Правка
точек кривых русел во вьюпорте пока в историю не попадает (точки — не свойства).

## Устройство

| Файл | Что |
|---|---|
| `GUI.h/.cpp` | оболочка: кадр, меню, раскладка (dockspace и `DockBuilder`), стиль и масштаб по DPI, уведомления, действия и переключатели |
| `OutlinerPanel`, `DetailsPanel` | списки окон свойств и свойства выбранного |
| `PropertyWidgets` | контролы свойств таблицей (числовые поля как в Blender), поиск, сброс |
| `EditHistory` | история правок свойств и действий кнопок: отмена и повтор |
| `StatsPanel` | оверлей и таблица времени (из `FrameStats`: строки «имя = формат») |
| `ConsolePanel` | консоль (дополнение, история) и лог (`Logger::recent`) |
| `CameraPanel`, `TextureLibraryPanel` | камера, текстуры |
| `Viewport` | выбор кликом, рамка, значки источников и эмиттеров, гизмо и его панель; сцену получает целиком (`GS::Scene`) |
| `EditorTypes.h` | раздел, запись Outliner, действие, переключатель |

Цвета темы заданы в sRGB и переводятся в линейные: задний буфер пишется через sRGB-вид. Масштаб — по DPI окна
(`GetDpiForWindow`), шрифт — Segoe UI из Windows (с кириллицей), без него — встроенный. ImGui — ветка docking
1.92.9b: архив `DownloadResources/imgui-1.92.9b-docking.zip`, если он есть, иначе с GitHub (`CMakeLists.txt`); ImGuizmo —
ветка master: `DownloadResources/ImGuizmo-master.zip`, иначе с GitHub (`src/ImGuizmo.cpp` собирается в движке).
