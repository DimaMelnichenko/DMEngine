# Съёмка сцены с другой камеры

Как SceneCapture2D / SceneCaptureCube в UE: кадр сцены с произвольного вида — в свои цели (HDR-цвет и глубина), а не в
буфер сцены главной камеры. Главный кадр от этого не меняется. На съёмке строятся кубическая карта отражений места
(`TODO.md`, «Кубическая карта отражений места»), а дальше — зеркала, карты местности, камеры наблюдения.

## Как пользоваться

Из кода — `Renderer::requestCapture( SceneCapture )` (`src/Engine/Graphics/Renderer.h`):

```cpp
SceneTargets targets;	// цели: HDR-цвет R16G16B16A16_FLOAT и глубина D32_FLOAT
targets.create( 256, 256, SceneCapture::clearColor );
SceneCapture capture;
capture.view = RenderView::perspective( position, forward, up, XM_PIDIV2, 1.0f, 0.1f, 100000.0f );
capture.color = &targets.colorTarget();
capture.depth = &targets.depthTarget();
capture.width = capture.height = 256;
capture.exposure = renderer.exposure();	// яркость × это — в цель (pre-exposure съёмки)
capture.done = [] { /* команды съёмки записаны: копия, чтение на CPU */ };
renderer.requestCapture( std::move( capture ) );
```

Цели создаются с `SceneCapture::clearColor` — им же съёмка их очищает (optimized clear value текстуры, иначе
предупреждение debug-слоя). Заказы встают в очередь: в кадре одна съёмка, следующая — в следующем кадре. `done`
вызывается в кадре сразу после записи команд съёмки — там ставят копию цели (в грань кубической карты) или отмечают, что
её можно прочитать: чтение на CPU (`GpuImages::captureTexture`) ждёт GPU, поэтому его делают после `Renderer::render`, как
снимок заднего буфера.

Проверочный инструмент — команда `capture` удалённого управления и консоли ([remote.md](remote.md)):

```
capture 500,20,215,4,5 balls.png                       # поза x,y,z,pitch,yaw — как у команды camera
capture 463.91,13.72,187.21,10.2,267.7 lake.png 512 512 90   # размер и поле зрения по вертикали, градусы
capture 300,30,960,-4,180 valley.dds                   # HDR как есть: яркость × экспозиция съёмки
```

По умолчанию размер — кадра, поле зрения — камеры, экспозиция — главного вида; съёмка ждёт, пока кадр устоится (10
кадров после смены плана). PNG и JPG — с простым тонмаппингом (ACES, приближение Narkowicz 2015) и sRGB, без
постобработки кадра (bloom, цветокоррекция, AgX): посмотреть, что снято. Снимок `capture` с позы камеры рядом со снимком
`screenshot` с неё же отличается тем, чего у съёмки нет (ниже): травой, водой, облаками, ближними тенями.

## Что рисуется

Съёмка идёт в конце кадра, после проходов главного вида (`Renderer::renderCapture` между `renderScene` и постобработкой):
карта теней, тень рельефа и гор, тень облаков, небо и освещение окружением этого кадра уже готовы. Проходы съёмки:

1. Очистка целей (`Scene capture clear`): цвет — `SceneCapture::clearColor`, глубина — 0 (дальняя плоскость).
2. **`opaque`** без depth prepass: непрозрачные и Masked пишут глубину сами, Masked — вариантом с `clip`, импостеры —
   тоже без глубины сцены (их глубина — запечённой поверхности).
3. **`sky`** — фон там, где сцена ничего не нарисовала.

Объекты решают, что рисовать в съёмку, по типу вида `RenderView::Kind::capture`, а не по его номеру:

| Объект | В съёмке |
|---|---|
| Рельеф (`CDLODTerrain`) | да; LOD — от точки съёмки, без уровней мельче листа (детальная земля у русел — только у главного вида) |
| Дальние горы (`FarTerrain`) | да, свои узлы на вид |
| Модели уровня (`ModelInstances`) | да; LOD — от точки съёмки, дальности — как у главного вида (не теней) |
| Расстановка: постоянные слои (лес, камни русел) | да — отбор кластеров и экземпляров по пирамиде вида съёмки в `scatter.cs` |
| Расстановка: кольцевые слои (трава, цветы, камешки) | нет — кольцо считается вокруг главной камеры |
| Небо (`SkyAtmosphere`, `HDRIBackdrop`, `SkySphere`) | да |
| Облака (`VolumetricCloud`), вода (`WaterSimulation`), частицы (`ParticleSystem`) | нет — их лучи, плитки и пул посчитаны под главный вид |

Вид съёмки — среди видов кадра для compute (`FrameContext::views`, номер — следующий за каскадами теней, всего видов —
`DM_MAX_RENDER_VIEWS` = 7): так расстановка раскладывает в него лес в том же проходе compute, что и для главного вида и
каскадов.

## Подмены вида

Ресурсы, которые считал главный вид, у съёмки не годятся. Новых флагов в шейдерах нет — подмены идут через константы вида
и привязки на время съёмки:

- **Затенение окружением по экрану** (GTAO, t126) — выключено: `cb_ambientOcclusion` = 0 в константах вида съёмки
  (`ConstantBuffers::setViewBuffer( view, parameters )` с подменёнными `FrameParameters`).
- **Туман** — по формуле: `cb_fogVolumeDistance` = 0 (объём тумана — над экраном главного вида).
- **Воздушная перспектива** — объём заново под вид съёмки: `SceneObject::beginCaptureView` у `SkyAtmosphere` считает
  его compute-проходом и привязывает в t106 (главный кадр свой объём уже прочёл; следующий кадр посчитает свой).
- **Тени** — только дальние: `ShadowCascades::bindForReceivers( солнце, false )` пишет константы приёма без каскадов
  (дистанция 0) — край тени рельефа, тень гор, дальний каскад леса и тень облаков. Каскады подогнаны под главную камеру:
  каскад выбирается по глубине её взгляда.
- **Экспозиция** — своя постоянная: буфер `ExposureState` съёмки (`exposure`, `sceneExposure` — `SceneCapture::exposure`,
  EV100 — главного вида) в t105 на время съёмки.

После съёмки рендерер возвращает константы главного вида, приём теней с каскадами и экспозицию главного вида: дальше
постобработка кадра.

## Как устроено

У рендерера для съёмки свои сборщик и команды (`m_captureCollector`, `m_captureCommands`): `buildCommands` и `executePass`
берут сборщик, команды и цели параметрами, а не членами, поэтому главный вид и съёмка идут одним кодом.
У прохода съёмки — её цели и размер, читает он карту теней. Время GPU и CPU — одной областью «Scene capture» на всю
съёмку (областей профайлера в кадре не больше `GpuProfiler::maxScopes`), меши съёмки не входят в счётчики кадра
(`meshes … in … draws` строки «GPU average»).

## Производительность

Кадр 1920 × 1080 с позы контрольной камеры — около 4,8 мс GPU и 0,9 мс CPU (Release, ноутбук, частота GPU закреплена):
это проход `opaque` со всем лесом, рельефом и моделями без prepass и объём воздушной перспективы. Грань кубической
карты 256² — в разы дешевле. Кадр без съёмки — как раньше: главный кадр не меняется (`check_frames.py` — паритет кадров
и времени).

## Ограничения

- Нет облаков, травы и цветов, воды, частиц, полупрозрачных — они считаются под главный вид.
- Тени — только дальние: модели уровня и ближний лес тени в съёмке не отбрасывают (каскады — главной камеры).
- Нет экранных эффектов главного вида: затенения окружением по экрану, объёма тумана (туман — по формуле), экранных
  отражений.
- В кадре одна съёмка; кубическая карта — шесть кадров или шесть съёмок по очереди.
- Экспозиция постоянная (своей автоэкспозиции у съёмки нет).

## Если что-то не так

- **Съёмка пустая или чёрная** — цели не того формата или размера (`SceneTargets::create` с размером съёмки), или `done`
  читает цель до конца кадра: чтение на CPU — после `Renderer::render`.
- **Предупреждение debug-слоя о цвете очистки** — цели созданы не с `SceneCapture::clearColor`.
- **В съёмке нет леса** — вид не попал в виды кадра для compute: съёмка взята из очереди в начале `Renderer::render`, до
  `prepareShadows`.
- **Главный кадр после съёмки другой** — что-то не вернулось на главный вид: константы вида, приём теней, экспозиция в
  t105 (`renderCapture`, конец).

## Файлы

- `src/Engine/Graphics/Renderer.h` / `.cpp` — `SceneCapture`, `requestCapture`, `renderCapture`, очередь съёмок.
- `src/Engine/Graphics/Scene/RenderView.h` — `RenderView::Kind::capture`, `RenderView::perspective`.
- `src/Engine/Graphics/Scene/SceneObject.h` — `SceneObject::beginCaptureView`.
- `src/Engine/Graphics/Scene/Sky/SkyAtmosphere.cpp` — объём воздушной перспективы под вид съёмки.
- `src/Engine/Graphics/ShadowCascades.cpp` — `bindForReceivers( …, cascades )`.
- `src/Engine/Graphics/ConstantBuffers.cpp` — `setViewBuffer( view, parameters )`.
- `src/Engine/Graphics/Scene/Terrain/CDLODQuadtree.cpp` — без уровней мельче листа у съёмки.
- `Shaders/scatter.cs` — отбор леса для вида съёмки (`captureView`).
- `src/Engine/EngineCommands.cpp`, `src/Engine/Engine.cpp` — команда `capture`, чтение и файл.

## Откуда подход

- Unreal Engine, Scene Capture 2D / Scene Capture Cube: вид со своей целью, флаги показа (что рисовать), своя экспозиция.
- Reflection Capture в UE (Sphere / Box) — снимок сцены в кубическую карту из точки: следующий шаг на этой съёмке.
