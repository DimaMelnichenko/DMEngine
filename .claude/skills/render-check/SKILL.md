# Проверка правки рендера

Суть — `docs/d3d12.md` §4 «Как проверять». Шаги:

1. **Эталон — до правки** (на чистом коде прошлого коммита): `python Tools/check_frames.py reference` (Release, частота
   GPU закреплена). Эталон Debug — `check_frames.py reference --config Debug`. Шейдеры компилируются при запуске: правя
   `Shaders\`, не снимать эталон параллельно — второй прогон возьмёт уже новые шейдеры.
2. **Сборка** — `cmd //c "Tools\build.cmd release"` и `debug` (только скрипт; папки `cmake-build-debug*` — CLion).
3. **Кадры и время** — `python Tools/check_frames.py`: пять контрольных камер ±1 к эталону (шум — маска эталона),
   «GPU average» не хуже. Разница там, где правка и должна менять картинку, — нормально: проверить карты
   `reference/release/last/<камера>_diff.png` и назвать в отчёте; разница по всему кадру на ±2 — сдвиг автоэкспозиции.
4. **Debug** — `python Tools/check_frames.py --config Debug`: «debug layer: clean». «Лог чист» — только если в `log.txt`
   есть «debug layer is enabled». Раскладку констант сверяет `ShaderCompiler` (строка «constant buffer layouts checked»).
   GPU-based validation (`--gpu-validation`) — только для правок слоя D3D12 (ресурсы, барьеры, дескрипторы, проходы).
5. **Намеренно сменили кадр** — после коммита эталоны заново (Release и Debug), иначе следующая проверка упадёт.

## Подводные камни

- **Шум времени GPU.** Фоновая нагрузка искажает «GPU average»: сравнивать сборки попеременно (старая, новая, старая,
  новая — копии exe в `cmake-build-cli-release`), а не два замера подряд; у камер обзора и шаров разброс ±6 %.
- **Только один движок.** Канал удалённого управления общий (`\\.\pipe\DMEngine`): не запускать второй, пока идёт
  `check_frames` или сессия `engine.py`.
- **Экспозиция.** После `set` времени суток или яркости — `camera …` (смена плана: экспозиция сразу), иначе снимок
  поймает адаптацию.
- **Сравнимые снимки** — `--nowind --noparticles --freezetime --nogui`; снимок с окнами — `screenshot файл.png gui`.
- **Подбор на глаз** — серия `engine.py` (`set` → `camera` → `screenshot`) и коллаж снимков; значение, которое подбирают
  на глаз, — поле окна и колонка базы, а не константа шейдера.
- Ответ команды дольше 60 с — главный цикл стоит: строки «Frame watchdog» в `log.txt`.
